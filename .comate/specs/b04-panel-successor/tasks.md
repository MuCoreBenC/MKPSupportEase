# B04 工作台接管 mkppanel —— 任务计划（第四版）

第三版在 Task 5 那里已经和实际做法不符：它写的是「`patch.rs` 补清单操作」，
但真做的时候定了另一条路 —— **这一页不走草稿与撤销栈**，
编辑方法直接挂在 `presets/catalog.rs` 上、各自一条独立 IPC。
理由记在 `wb_add_version` 的文档注释里：「加一个版本」低频、逆操作直接，
为它复制一整套状态机换来的只是一个"还没保存"的中间态，而那个中间态本身就是新的 bug 来源。

**这一版的写法原则（来自你的指正）：不机械复制测试，按每个操作各自的写入风险写判据。**
三种操作的风险互不相同，所以判据也不该长一样：

| 操作 | 它**独有**的风险 | 对应判据 |
|---|---|---|
| 加版本 | 改已有文件时把别处重排 | `one_edit_only`：删掉段为空、插入段含新 ID |
| **加机型** | **覆盖一个已存在的文件**（不可逆）；ID 与别名相撞 | 存在即拒绝；新文件能被自己的 loader 读回 |
| **删版本** | **跨文件孤儿引用**（`[params.machineVariants]` 里的 `机型:版本` 键）；不可逆 | 删前报出会变成孤儿的引用；`one_edit_only` 插入段为空 |
