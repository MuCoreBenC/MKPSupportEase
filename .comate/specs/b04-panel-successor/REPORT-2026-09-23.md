`presets/machines/A1.toml` 全文结构（这就是「加一个版本」要动的那个文件）：

```toml

[dimensions.bedSize]      depth = 255.0  width = 260.0
[dimensions.movementRange] minX = -40.0  maxX = 260.0  ...
[dimensions.glueArea]     glueMinX = -40.0 ... wipeX = 252.0

[dimensions.flags]        gcodeMarker = ';===== machine: A1'  hasSecondFan = false

[[versions]]                       # ← 一个版本 = 一个这样的块
id = 'STANDARD'
name = '标准版'
presetFile = 'A1.toml'             # 指向产物文件
recommendedBundle = 'A1_default'
tag = '推荐'
description = '官方标准配置，适合大多数用户'
```

**版本只有这 6 个字段**，没有"归档"这类状态 —— 这一点对 §7 的决定很关键。

参数值不在这里，在 `param_registry.toml` 里，形状是：

```toml

valueType = 'float'
defaultValue = 0.0                 # 出厂默认，全局单值

[params.machineVariants]           # ← 机型 / 版本的差异都在这张表
```

## 7. 我做的三个决定（原 Task 11.4），请你过一眼

删掉自造的 JSON 之后，版本身上那三件事要有个去处。我的决定是**都不搬，而是删**：

### 7.1 改名 → 归「机型与版本」页，删掉 `RenameVersion`

版本名就是机型文件里的 `name`，而那一页已经能直接改它（`wb_set_version_field`）。
留一个"在参数页改名、保存时才生效"的入口等于同一个字段两个真相。

### 7.2 归档 → **不做**，删掉 `ArchiveVersion` / `RestoreVersion`

理由三条：

1. 源数据里**没有这个概念**，版本只有 6 个字段。加 `archived = true` 是我们自造的字段，
   客户端读到它会忽略 —— 那就是"界面上有个状态，交付面上没有"。
2. 「暂时不想交付这一版」的正解是**生成那一步不勾它**（Task 17 的 Diff → 写入），
   而不是在清单上打一个灰标记。清单是交付面，不该承载临时意图。
3. doc §4 写着不发明新 SOP。归档是我上一稿发明的。

代价写明白：树上不再有"灰着的版本"。不想要某一版就删掉它（已有两步确认 + 孤儿检查）。

### 7.3 BBS 选择 → 归套餐那一层，删掉 `SetBbs`

版本已经有 `recommendedBundle`，机型有 `defaultBundle`，都指向 `bundles/*.toml`。
在版本上另存一串 asset id 等于把套餐的内容复制一份到版本上 —— 两处真相。
改法是改 `recommendedBundle` 指向哪个套餐，归 Task 15（机型与资源页）。

### 7.4 这三条一起推翻了什么（**这段是要你注意的**）

按上面三条走下去，`domain/patch.rs` 里 12 种动作会**只剩值编辑那几种**：
`NewVersion` / `CloneVersion` / `MoveVersion` / `PurgeVersion` 也一起删 ——
清单类编辑全部归「机型与版本」页，`domain` 只管值。

**这会删掉 Task 8 做的一半**：我当时让草稿里的「新建版本」在保存时落进机型文件，
并为它写了两条回归判据（那条死胡同的正面测试）。按新决定，那条路径由
`wb_add_version` 负责，草稿里不再有"新建版本"这件事。

我认为该这么做，理由是它让「一页一件事」在结构上成立，而不是靠自律；
但这是一次推翻，所以单独列出来。如果你更希望参数页也能直接加版本（少切一次页），
说一声，那我保留 `NewVersion` 这一条，其余三条照删。
