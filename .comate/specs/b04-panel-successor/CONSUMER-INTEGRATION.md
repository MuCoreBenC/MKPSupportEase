# B04 消费端接入 Spec

状态：Draft 0.1；依赖 `DATA-CONTRACT.md`，具体路径/schema 以 P0 追踪结果为准。

## 1. 消费端职责

消费端只负责加载、校验并使用发布产物；不负责编辑源 TOML、解析工作台草稿、合并继承规则或生成配方。

消费端必须通过单一入口加载数据。页面/业务模块不得各自拼路径、各自解析文件或各自实现 fallback。

## 2. 建议模块边界（命名待贴合现有代码）

- `contract`：共享 DTO、版本常量、字段语义。
- `loader`：定位并读取已发布产物；不负责业务决策。
- `validator`：校验 contract version、ID、必需字段、类型/范围。
- `repository`：向业务层提供已校验的数据；不暴露半解析状态。
- `error`：稳定错误码及可定位上下文。

不要为了照搬此命名而新建重复层。先映射到现有架构；若已有等价职责，复用并补齐测试。

## 3. 加载状态机

`NotLoaded → Loading → Ready`

失败路径：`Loading → Failed`

- `Ready` 只能在整份产物完成读取与校验后进入。
- `Failed` 必须保留失败原因；不得转成空列表、内置默认值、旧 mock 数据或“加载成功”。
- 从 `Ready` 刷新失败时，既有已确认数据可以继续显示，但必须标记刷新失败；不得把半成品覆盖进去。
- 初次加载失败时，页面显示明确错误与重试入口，不伪造可编辑数据。

## 4. 读取与兼容要求

1. 从 ADR 固定的发布根目录读取；禁止隐式探测多个目录后挑一个“能读的”。
2. 先校验 manifest 与产物 hash，再解析业务内容（若 manifest 被 ADR 确认）。
3. 校验版本后再解码 DTO；不支持的 major version 明确拒绝。
4. 必需字段缺失、ID 重复、类型错误、范围非法、文件截断均返回结构化错误。
5. 可选字段是否忽略必须由 schema 明确；未知字段不能被无声丢弃后再回写。
6. 消费端永不回写交付产物；编辑回到源端工作台。

## 5. UI / IPC 映射

- 前端只调用统一 IPC/应用服务，不直接 `fs` 读取源文件或交付物。
- IPC 返回明确的成功/失败结果；失败包含稳定 `code` 与用户可读消息。
- 未接通真实 loader 的页面应隐藏入口或呈现明确的未就绪状态；不得用 mock 数据冒充真实加载成功。
- 重试只重试同一契约入口，不偷偷切换到另一套数据源。

## 6. 双端共享测试夹具

由契约目录维护最小 fixture 集，generator 和 consumer 都引用同一组输入/产物：

| Fixture | Generator 预期 | Consumer 预期 |
|---|---|---|
| valid-current | 成功生成 | 成功加载为 Ready |
| missing-required | 失败，不发布 | 若手工构造产物则拒绝 |
| unsupported-major | 不适用/按生成目标版本处理 | 明确拒绝 |
| invalid-type-or-range | 拒绝生成 | 拒绝加载 |
| duplicate-id | 拒绝生成 | 拒绝加载 |
| truncated-artifact | 不应发布 | 拒绝，不能应用部分数据 |
| unknown-optional-field | 按 schema 规则生成 | 按声明策略处理 |
| deterministic-rebuild | 输出稳定 | 同 hash/语义数据可重复加载 |

## 7. 验收门

- [ ] 能指出消费端实际 loader 的文件路径与调用入口。
- [ ] 旧数据入口和 fallback 的所有调用点已枚举。
- [ ] DTO 与共享契约逐字段对应；无前端私有副本。
- [ ] 加载失败不会返回成功态或部分数据。
- [ ] 当前版本、缺字段、损坏文件、不支持版本均有测试。
- [ ] 生成器产物可直接被消费端加载，端到端测试使用真实序列化产物而非手写假对象。
- [ ] 记录本地实际执行的命令、结果与未运行项。
