    **两处补充的设计（doc §4.4 已同步）**
    - `ApplyResult` 多一个 `undoable: bool`。**`PurgeVersion` 与 `MarkBuilt` 不进撤销栈**：前者走「二次确认 + 回收站」，后者是生成的记录、撤销一条「生成过」没有意义。刻意不做「有些删除能撤销、有些不能」——「看情况」的撤销比「从来不能」更糟，用户点撤销前得先想这个版本保存过没有。`undoable` 为 false 时界面不给撤销按钮，而不是给一个按下去没反应的。
    - 反向 patches **倒序返回**（正向 A→B→C，反向 C⁻¹→B⁻¹→A⁻¹）。同一个键连改两次时，顺序错了就回不到原状；有单测盯着。
    - 顺手多两条正确性判据：改成和现在一样的值不记草稿（脏计数不虚涨）；改了又**改回落盘的值**要把草稿那一条拿掉（否则保存按钮一直亮着）。

    **7.2 的「暂无资源」判据比原计划多一个条件，理由写在 derive 的模块文档里**
    原计划是「没有 MKP 产物 && 没有 BBS」。照这个判，**刚在 A1 下新建的版本也会显示「暂无资源」**—— 而它点一下生成就有了，那句话会让人以为没救。所以加第三个条件：**这一版的参数全是出厂默认**（我们没写过，上游也没给这台机型/这一版差异）。A2L 命中（上游给它 0 项机型差异），A1 下的新版本不命中（A1 的上游机型差异非空）。
    「未配置」（有效配方为空）是第三件事，单独一个布尔位，不占状态档。

    **7.4 的单元格是三种 kind + 一个 `editable`，不是四态**
    doc §8.3 的第三条分支（选中了就升级成真控件）**是前端的事** —— 后端不知道现在选中的是哪一格。所以后端给 `NotApplicable` / `Gcode` / `Value` 三种 kind，外加 `editable` / `reason` / `blocked` / `own` / `dirty`。

    **两个真 bug，都是接 IPC 时才暴露的**
    1. `Committed.versions` 原来只按「我们写过文件的版本」建，于是**干净仓库里改任何一版都被判成「版本不存在」**——而那一版明明在上游清单里。改成「上游声明的每一版都先建一条空记录，文件只是往里填值」。
    2. 由此暴露第二件事：**上游还声明着的版本删不掉**。版本清单是上游的，删掉我们的文件只是「这一版没有自有改动了」，它照样出现在树上。所以 `PurgeVersion` 现在只对两种版本开放 —— 上游已经不再有的孤儿、和草稿里新建还没保存的；上游还声明着的只能**归档**，并且拒绝时那句话直接指向归档。
