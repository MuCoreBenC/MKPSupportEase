# 预设列表「本地 / 云端」现状梳理与问题清单（2026-10-08）

> ## ✅ 结论（同日）：模型已定并已实施
>
> 见 [`PRESET-ASSET-LIBRARY.md`](PRESET-ASSET-LIBRARY.md)。
>

> 3. 这套列表底下到底有几本账、各记什么、互相联不联动。
>
> 现象出自 2026-10-08 真机截图（云端 9 项 / 本地 5 项）。

## 0. 三句话版本

1. **一个官方预设在这台机器上最多有四份"身体"**（官方基线 / 隐藏摘要副本 / 你的工作副本 / 归档旧版），而界面上只让你看见其中一份（工作副本）。
2. **云端行的「已下载」判的是你看不见的那一份（官方基线）**，不是你在本地表里能看见、能删掉的那一份 —— 所以"你删了它还说已下载"不是显示 bug，是三本账各记各的、互不联动。
3. **表格里「已下载」是一段灰字、不是按钮** —— 想重新下载，表格里没有入口（右键菜单里其实有一个「下载」一直在，但没有任何视觉提示，而且下载完状态也不会变，因为基线本来就没缺）。

## 1. 一个预设的四个落点（数据模型）

程序内部（`<appDataDir>/`，用户正常看不到）：

| 落点 | 是什么 | 谁写它 | 它服务谁 |
| --- | --- | --- | --- |
| `catalog.json`（+ `archive/catalogs/*.json` 版本链） | **目录**：云端登记了哪些文件、每份的 SHA / 落点 / 机型 / 版本 / 发布时间 | 检查更新（从数据源拉） | 云端表的行全部来自它 |
| `delivery/mkp/presets/<官方原名>.toml` | **官方基线**：下载落点。就是"这台机器上下过这一版官方字节"的唯一证据 | 下载管道 | **云端行「已下载」的判定锚点** |
| `baseline/<sha256>.toml` | **隐藏摘要副本**：按内容摘要寻址，每下载过一版存一份，永不覆盖、无删除入口、无 GC | 下载管道（落基线成功后附带写） | ①参数页「恢复默认」的取值依据；②**云端行「旧版 ×N」徽章的判定锚点**；③工作副本血统里 `based_on_sha256` 指向的东西 |
| `archive/<catalog.path>` | **归档**：换版本时被换下来的旧官方字节（保留最早一份） | 下载管道（换版时） | 交付四态"这是旧版本"的证据；展开详情里「旧版本 N 份」 |

用户可见（`presets-mine/`）：

| 落点 | 是什么 | 谁写它 | 它服务谁 |
| --- | --- | --- | --- |
| `presets-mine/<官方原名>-<发布日期>.toml` | **你的工作副本**：官方正文 + 三行血统（基于哪一版、来源 sha），下载那一刻自动铺一份 | 下载收尾（幂等）；之后用户自己编辑 / 改名 / 另存 / 删除 | **本地表（MKP 档）唯一的行来源**；「应用」的对象；文件名带官方发布日（`A1-fast-2026-10-15.toml`），同日撞名补 `-01` |

**下载一次，四个落点各发生什么**：

```text
                        目录 catalog.json（云端有什么、SHA 多少）
                                │  点「下载」（数据源地址 + 目录里的 path）
                                ▼
        下载管道：取字节 → SHA / 大小校验 →（旧份与目录不同才）进 archive/ → 原子落盘
                                │
        ┌───────────────────────┼────────────────────────┐
        ▼                       ▼                        ▼
  delivery/ 官方基线     baseline/<sha256>        presets-mine/ 工作副本
  （云端「已下载」锚点）  （「旧版 ×N」锚点）       （本地表唯一的行；可见、可删、可改）
```

**关键：四条线只有"下载"这一个写入口把它们串起来过；此后它们各自独立。**
你在 `presets-mine/` 里做任何事（改名、编辑、**删除**），不会碰 delivery / baseline / archive。

## 2. 界面上的几个状态，各自看的是哪本账

`src/app/presets/` 前端只做搬运，判词全来自后端。三套账：

| 你看到的 | 它的判据（唯一的真相源） | 你看得见吗 |
| --- | --- | --- |
| 云端行「已下载 / 有更新 / 未下载」 | `delivery/` 里**存在该文件且字节与目录登记一致** → 已下载；盘上有但字节对不上 → 有更新；没有 → 未下载 | **看不见**（程序内部区） |
| 云端行「旧版 ×N」徽章 | `baseline/` 里按 sha256 存着这个文件名的 **N 份"非当前版"** 摘要记录 | **看不见** |
| 本地行的存在与「应用」 | 扫 `presets-mine/` 目录（盘就是底账） | **看得见** |

也就是说：

- 「已下载」= **官方基线在不在**（第二本账）
- 「旧版 ×N」= **摘要副本里躺了多少份旧版**（第三本账）
- 本地表有什么 = **presets-mine 里现存什么**（第四本账）

**三本账互不联动** —— 这就是所有困惑的总根源。

## 3. 你能做的那几次"删除"，各删掉了什么

| 你在哪删 | 删的是哪个落点 | 云端「已下载」变吗 | 「旧版 ×N」变吗 | 本地表变吗 |
| --- | --- | --- | --- | --- |
| 本地表右键 → 删除（MKP 档全是这个） | `presets-mine/` 工作副本，**真删** | **不变**（delivery 里那份还在） | **不变** | 该行消失 |
| 展开详情 → 「旧版本 N 份」抽屉 → 删除 | `archive/` 里一份旧官方字节 | 不变 | **不变**（徽章看 baseline，不看 archive） | 不变 |
| （只有切片器档有）本地表删官方交付行 | `delivery/` 官方基线 | 变（回「未下载」） | 不变（徽章仍在，可能出现"未下载 + 旧版 ×N"） | 行消失 |
| 云端表 | **没有删除**（产品规则：云端表一味只读，像浏览器下载列表） | — | — | — |

两个现状要点：

- **MKP 档没有任何"删掉官方基线那一条"的界面入口** —— 云端表不许删（既定裁决），本地表 MKP 档只列工作副本。基线进了 delivery 就只进不出（除非手动去文件系统里删）。
- 所以对用户来说，**"我删了"和"系统里少了什么"永远是两件事**：你能删的（工作副本、归档）都不参与云端状态；参与云端状态的（基线）你删不到。

## 4. 用你的两张截图逐条对账

### 4.1 云端表（9 项）

顶部：`未下载 3 份 · 需更新 1 份` ＋ 按钮 `下载并更新 4 份`
→ 这是把云端表里所有 `releaseState != 'ok'` 的行数出来：3 份完全没下过 + 1 份盘上是旧版（主词在展开详情里写「有更新」，按钮照样叫「下载」；**已下载的 5 份不进这一批，永远不进**）。

| 行（云端的名字） | 你看到的 | 实际上是 |
| --- | --- | --- |
| `A1_MINI-fast.toml` `旧版×2` | 已下载（灰字） | delivery 里有当前版字节；baseline 里另有 2 份非当前版摘要 → 徽章。**但本地表里已经没有 A1_MINI-fast 的任何一份**（只有 fastv3.3 的那份）—— 这就是你说的"我本地删了它还说已下载"：你删的是工作副本，徽章与「已下载」全都不看工作副本 |
| `A1_MINI-fastv3.3.toml` | 已下载 | delivery 有；本地表里有对应工作副本 `A1_MINI-fastv3.3-2026-10-06.toml` ✓（这一行是"账对得上"的样子） |
| `A1_MINI-standard.toml` | 已下载 | delivery 有；**本地表里没有对应的工作副本**（同第一行的情况） |
| `A1-fast.toml` `旧版×1` | 下载（按钮） | **这一行自相矛盾的两半**：徽章说"下过一版旧的"（baseline 里有），状态说"没下/有更新"（delivery 里没有当前版字节）。两半各自都对，凑在一行上就像系统前后不一 |
| `A1-fastv3.3.toml` | 下载 | 云端有、完全没下过 |
| `A1-standard.toml` | 下载 | 云端有、完全没下过 |
| `P1S-lite.toml` | 已下载 | delivery 有；本地表里没有对应工作副本 |
| `P2S-standard.toml` | 下载 | 云端有、完全没下过 |
| `X1C-lite.toml` | 已下载 | delivery 有；本地表里有 `X1C-lite-2026-10-06.toml` ✓ |

台账：`共 9 项`（当前表的行数）· `仓库 9`（这一档类型在全机型下的官方文件数）· `我的 5`（presets-mine 里的文件数）。
**三个数字三套口径**，你在一个屏幕上同时看到它们。

### 4.2 本地表（5 项）

| 行（本地的名字） | 说明 |
| --- | --- |
| `A1_MINI-fastv3.3-2026-10-06.toml` | 下载时按官方发布日期自动命名的工作副本 |
| `A1-fast-10081315.toml` | 早期命名（数字戳）留下的旧副本，和下面两份同属 A1-fast |
| `A1-fast-2026-10-08.toml` | 后来又下一次生成的 |
| `A1-fast.toml` | 没有日期后缀的一份（官方正文没写 `release_time` 时退回原名） |
| `X1C-lite-2026-10-06.toml` | 同第一行 |

本地表这一侧的问题不是"状态算错"，是**同一个预设的三份不同时代副本并排躺着，名字还都不一样**：

- **云端行名** = 官方原名（`A1-fast.toml`）
- **本地行名** = 原名 + 官方发布日（`A1-fast-2026-10-08.toml`）、或没有日期、或历史命名
- 用户在两张表之间**对不上号**：这个 `A1-fast.toml`（云端）和我那几个 `A1-fast-*`（本地）是同一个东西吗？

### 4.3 那一条提示

`已删除 A1_MINI-fast.toml 的这份旧版本 —— 删了就找不回（云端只有最新版）`

这是归档抽屉里删掉一份 `archive/` 旧版后的**瞬时提示**（操作完弹出来的，不是持久状态）。
它容易被读成"这一行发生了什么"，但删掉的 `archive/` 那份**不影响屏幕上下任何一格**（云端状态、徽章、本地表全都不动）—— 唯一变化藏在展开详情里「旧版本 N 份」那个数字。

## 5. 问题清单

**P1 · 「已下载」的锚点是隐藏区，跟用户能删的东西脱钩。**
用户心智："下载 = 我得到一份预设"；系统的"已下载"= "内部基线区有一份官方字节"。
用户删掉工作副本 = 他心里"这个预设没了"；系统说"还在"。**两边都没错，是两个定义。**

**P2 · 「旧版 ×N」与「已下载」是两本账，会出现"下过又没下过"的组合。**
`A1-fast.toml` 一行同时说"旧版 ×1"（baseline 说下过）与"下载"（delivery 说没下过）。同理，删除 delivery 后可能出现"未下载 + 旧版 ×N"。徽章的 tooltip 还写着"它们在你自己的文件里" —— 但用户删过工作副本时，那些旧版工作副本**并不在本地表里**，这句话会骗人。

**P3 · 「已下载」是一个死掉的灰字，重下没有入口。**
表格里 `ok` 的行操作列只有灰字「已下载」（不可点）；批量按钮只含非 `ok` 的行；云端表菜单里的「下载」项**其实对已下载的行一直可用**（点了会走同一条管道），但：
- 没有任何视觉提示它存在（只有右键 / Shift+F10 才能看到菜单）；
- 点了以后状态**也不会变**（delivery 字节相同，纯 no-op —— 见下）—— 唯一实际效果是：如果你删过工作副本，它会**把那份补回来**（血统幂等，见附录）；如果工作副本还在，什么都不发生。
**"重下"这个动作在系统里的真实语义 = "补回我删掉的工作副本"，但界面没有把这个语义说出来过。**

**P4 · 三条删除路径三种语义，删完都觉得"没变化"。**
见 §3 对照表。用户无法从界面上知道："我删的这个，到底是哪个层次的删除、影响面是什么。"

**P5 · 命名不统一 + 同一预设多份并存。**
云端原名 vs 本地"原名+日期"（`A1-fast` 在两张表里各叫各的）；同日重下会补 `-01`；早期还有无日期 / 数字戳命名。本地表里同一个预设可以同时躺着三份（改名过的、下过的、导入的），**没有任何一列告诉你"它们其实是同一个官方预设"**。

**P6 · 一屏四个数字，四套口径。**
`共 9 项`（筛后行数）、`仓库 9 · 我的 5`（全机型的类型计数 + 用户文件数）、`未下载 3 份 · 需更新 1 份`（非 ok 行分档计数）、`旧版 ×N`（baseline 计数）。
谁跟谁不是一个维度，界面上不说。

**P7 · 状态主词藏在展开详情里，行上的灰字替它承担了两个语义。**
行上没有"状态"这一列；"已下载 / 有更新 / 未下载"只在点开后的详情里写。表格里的灰字「已下载」同时被读成"下过了（状态）"和"不能点（动作）"，但它其实只是后者（因为前者由别的账本决定）。

## 6. 作者提的两个方向，各自要先回答的问题

### 方向 A：「云端的右边那个就只有下载按钮」

（即：云端就是一张**下载列表**（像浏览器下载列表），行行给一个可点的「下载」，不放"已下载"灰字。）

要回答：

1. 行上还要不要显示"我下过没有 / 本地有没有"？如果要，放哪（状态列？副标题？）—— 还是彻底不给，靠下载后的提示说话？
2. 对**已经下过、工作副本也还在**的行，点「下载」是 No-op（字节相同不动）—— 允许点但什么都不发生，还是给一句"本机已有，未改动/已补回"的反馈？还是**不许重复点**（那就又回到灰字了）？
3. 对**下过但工作副本被删了**的行，点「下载」= 补回工作副本（现在的实际行为）——这个语义要不要成为明说的"恢复"？
4. 「旧版 ×N」徽章留不留？（它来自另一本账，和"下载列表"的简洁语义冲突。）

### 方向 B：「状态根据我本地判断」

（即：「已下载」改成看用户能看见的那一份 —— `presets-mine/`。）

要回答：

1. **判到什么程度算"有"**：
   - 文件名匹配（用户一改名就断）；
   - 还是血统匹配（文件头 `based_on_sha256`，改名 / 编辑都还认得出；但导入的、早期无血统的副本认不出）；
2. work副本被**编辑过**（内容变了，血统还指着旧版官方）算不算"有"？—— 算，那"已下载"的含义就变成"我有这个预设的某一份副本"（跟官方版本无关）；
3. delivery / baseline 这两本账还留不留？如果留（它们有别的职责：恢复默认、换版比对），那就必须接受"内部有、用户没有"与"用户有、内部没有"两种态同时存在 —— 界面怎么把这两个维度各说一句话；
4. 那"云端有新版本"这件事怎么表达？（现在靠目录 SHA 比 delivery；改成比工作副本血统的话，逻辑另写。）

### 两个方向共同要回答的

5. **删了以后怎么重下**（用户的原始诉求）：重下的目标是什么 —— 补工作副本？刷新 delivery？两者都要？
6. 云端行「下载」如果永远可点：**重复下载会创建什么**？（不会重复建工作副本 —— 血统幂等、字节相同则不重写基线，等于纯 no-op。要不要给可见的"已补回 / 未改动"回执？）
7. 提示语与文档里"删了就找不回"这类话，是否要区分"删的是工作副本（可恢复）/ 删的是归档（找不回）/ 删的是基线（界面无入口）"。

## 7. 供讨论的问题清单（可以直接拿去跟外部助手对）

1. 「已下载」对用户应该是什么意思：**"官方字节在我机器上"** 还是 **"我有一个能用的副本"**？这两个定义分别要求界面说什么？
2. 云端操作列：恒定「下载」按钮 vs 状态灰字 vs 灰字可点 —— 选哪个？理由？
3. 内部账（delivery / baseline / archive）要不要继续对用户隐形？隐形的代价就是"删了它还说有"这类解释不了的现象。
4. 工作副本的删除，要不要联动些什么？（不动内部账 / 给一句"云端仍标记为已下载" / 或反过来改状态）
5. 云端表的"已下载"与「旧版 ×N」两个维度，合成一个还是继续分开？合成后怎么向用户解释"我删过"？
6. 重下入口放哪：行按钮 / 右键菜单（现在就有）/ 在"已下载"灰字上直接变成"重新下载"链？
7. 命名要不要统一（云端显示"它在本地叫什么" / 下载命名换规则 / 或本地行加一列"源自云端哪一份"）？
8. 一屏四个数字（共 N / 仓库·我的 / 未下载·需更新 / 旧版 ×N）怎么收敛到用户能背下来的一句话？
9. "云端 = 只读下载列表"这条既定规则要不要在**操作列**上体现（即行行给下载按钮），还是保留"已下载"的只读态？
10. 用户想不起来自己删过什么时，有没有一个地方能看见"这台机器上这个预设的完整账"（四本账并排）？
