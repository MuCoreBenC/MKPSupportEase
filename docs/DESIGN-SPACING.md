# 间距设计原则

适用于 MKP 客户端界面（预览器自身的工具栏不在此列）。目的是让"边距该给多少"有据可循，而不是每次凭感觉调。

## 参考依据

| 来源 | 结论 |
| --- | --- |
| Fluent 2 Design System · Layout | 间距是 4px 网格上的令牌梯度（`size40 = 4` … `size560 = 56`）；卡片内边距 24；密集内容页边距从 16 起步 |
| macOS HIG / Interface Builder 布局指南 | 窗口内容距窗口边 **20pt**；相邻控件之间 8pt |

这两套值是**密集型内容**的下限。展示型页面（大标题 + 成段留白）必须显著大于它，否则文字会贴边。

## 原则

1. **4px 网格**：clamp 的上下限取 4 的倍数，不出现 13、18、30 这类值；中间的连续值由浏览器插值，不必落在网格上。
2. **连续缩放优先于档位常量**：同一个属性不要按 ultra / wide / compact / mini 分别给常量。档位切换会在阈值处产生一帧突跳——边距、字号、信息列宽同时变化时，整页看起来像"抖了一下"。改用 `clamp(下限, 容器比例, 上限)`，值随窗口连续变化，阈值消失。
3. **只为"结构改变"保留断点**：需要换布局形态时（收起大图、页签变下拉）才用断点，且用容器查询而不是视口媒体查询——组件的可用空间才是判断依据。
4. **展示型页面的左右边距 ≥ 内容区宽度的 5%**，同时不低于 macOS 的 20pt 底线（体现为 clamp 的下限 20px、比例项 5cqw）。
5. **同一条左基线**：标题、eyebrow、数值列、按钮的左边界必须对齐，不做二次缩进。
6. **底部留白 ≥ 顶部留白**，让视觉重心略微上移。
7. **卡片/浮层内部一律 24px 起步**（与 Fluent 一致），不与页面边距混用同一个数值——页面边距管"内容离窗口多远"，卡片内边距管"内容离卡片边多远"，两者不是同一件事。

## 当前取值（v0.0.8 机型页）

比例项以 `.page` 为容器（`container-type: size`），故 `cqw` / `cqh` 是内容区宽高，而不是浏览器视口。不支持容器查询单位的浏览器退化为 `vw` / `vh` 同形写法。

| 位置 | 下限 | 容器比例 | 上限 |
| --- | --- | --- | --- |
| 页面左右边距 | 20px | 5cqw | 96px |
| 页面上边距 | 16px | 2.6cqh | 44px |
| 页面下边距 | 20px | 3.2cqh | 52px |
| 信息列宽度 | 300px | 34cqw | 480px |
| 大图槽位左内边距 | 16px | 2cqw | 32px |
| 机型名字号 | 26px | 3.6cqw | 48px |
| 副标题字号 | 22px | 2.5cqw | 34px |
| 参数名列宽 | 74px | 7cqw | 88px |
| 上一页热区宽 | 24px | 2.8cqw | 36px |
| 页签左右内边距 | 9px | 1.1cqw（容器为标题栏） | 12px |

唯一的结构断点：`@container home (max-width: 620px)` 收起大图、信息列占满、内容顶端对齐。620 来自"信息列下限 300px + 两侧边距 + 大图至少 260px 才有意义"。

## 大图微移的网格

调试期拖动大图可按 Shift 吸附到网格（Ctrl / Alt 强制自由），网格画在图外面的包围盒上、不随图移动。网格步长用 px（默认 24）而不是百分比：px 网格是正方形，百分比网格在扁窗下会被拉成长方形。代价是微移量以百分比存储，窗口尺寸变化后图会漂离网格线 —— 这是有意取舍，下次拖动会重新吸附。

## 超宽窗：宽度换密度还是换页边

窗口宽高比很大时（例如 1960 × 700，比值 2.8），所有连续值都到了 clamp 上限，剩下的宽度就变成纯空白 —— 留白不是设计出来的，是"没人要"的结果。v0.0.9 并行实现两种策略，用调试面板切换对比：

| 策略 | 做法 | 适合 |
| --- | --- | --- |
| 摊开 spread | 信息列在超宽时拆两栏（身份信息 \| 参数表），参数表自身也变两列 | 桌面工具：宽度用来减少滚动与翻页 |
| 居中 center | 白底仍铺满窗口，只有 `.pane` 限宽 1400px 居中；右侧只露出 1/5 的卡片层例外，内容靠左排 | 阅读型页面：把空白变成对称页边 |

居中这条踩过两次坑，都记下来：

1. 一开始把 `max-width` 加在 `.pane` 上而没有排除卡片层 —— 卡片内容也被居中，而它只露出左边 1/5，那 1/5 正好是卡片自己的页边，看到的是一片空白，窗口越宽越空。
2. 然后把限宽提到 `.deck` —— 白底跟着缩到 1400px，窗口两侧露出 shell 的灰色渐变，也不对。**该限宽的是内容，不是底。**

最终做法：白底铺满，`.pane` 居中，`SlideDeck` 给三层加 `data-layer="plane" / "card" / "exit"` 作为跨模块的样式契约。露出的卡片**仍是居中布局**，只额外加一个负位移 `--pane-shift: min(0px, (1400px - 100cqw) / 2)` 把内容盒推到卡片左边缘 —— 这样露出的部分有字，而动画终点 `translateX(0)` 精确等于平面的居中位置。

推入动画在居中模式下改成"先滑完，再放大"（`translateX` 在 60% 结束，之后只做 scale，`transform-origin: center center`），内容用一段等时长、同缓动的 `pane-settle` 在同一刻归零 —— 文字跟着卡片滑过来后就停在最终位置，不再有接管瞬间的横跳。返回方向用 `pane-tuck` 镜像（延迟 45% 后移回）。

残余位移只剩 scale 带来的那一点：0.94 → 1 时距中心 604px 的文字横移 (1 − 0.94) × 604 ≈ 36px，是收敛的，读作"字随卡片长大"。想彻底归零只能让卡片多露出一个页边的宽度（露出 = 页边 + 400px 内容），代价是卡片露出约 35% 而不是 20%。




判断"是否超宽"用宽高比而不是绝对宽度：1600 × 1200 不需要摊开，1600 × 620 很需要。阈值取 `@container home (min-aspect-ratio: 2/1)` —— 16:9 是 1.78 不触发，21:9 是 2.33 触发。

摊开时信息列上限 900px，仍守住行长可读性上限，不做无限拉伸；大图上限保持 640px，多出来的宽度一律不给图。

## 硬规则：连续量绝不挂在断点上（v0.0.10 起）

`max-width`、边距、字号这类**连续量**一律无条件生效，不允许写在 `@container` / `@media` 的条件里。踩过的坑：v0.0.9 把居中写成 `@container home (min-aspect-ratio: 2/1) { .pane { max-width: 1400px; margin-inline: auto } }`，结果窗口在宽高比 2.0 附近拖动时，`max-width` 从 `none` 跳到 `1400px`，整块内容瞬间平移约 38px —— 等于把前面花一整版消除的档位跳变又请回来了。

正确写法是 `.pane { max-width: 1400px; margin-inline: auto }`：窄于 1400 时不生效，宽于 1400 时页边从 0 连续增长。断点只留给**结构形态变化**（收起大图、页签变下拉）。

## 动画原则：缩放作用在容器，不作用在内容

卡片推入这类"从小长到大"的动画，如果让内容跟着 `scale`，内容里的每个元素都会随距缩放中心的距离产生位移 —— 距中心 600px 的文字在 0.94 → 1 时会横移 36px，图片也会涨 6%，看起来就是"落位时抖一下"。

v0.0.10 的做法是分层：卡片本体只做位移，白底 / 圆角 / 阴影单独放在 `.face` 层并只让它缩放，内容层从头到尾都是最终尺寸、最终位置。放大阶段只有白底在向两侧扩张，内容一个像素都不动，落位接管平面时天然对齐。

代价是"放大感"变弱（只剩白底在长），需要更强的观感就加大 `.face` 的起始缩放幅度，而不是把内容拉回缩放里。

## 修改流程




改边距时先看这张表，确认新值仍满足原则 1、4、6；若要打破某条原则，在这份文档里补一行说明为什么，而不是直接改 CSS。新增响应式属性时默认写 clamp，只有确实要换布局形态才加断点。
