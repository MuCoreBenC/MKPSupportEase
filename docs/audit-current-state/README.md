## 3. 执行摘要

### 3.1 这个软件现在是什么

一个 **Tauri 桌面客户端 + 一个发布端（工作台）+ 两个 Rust 内核 crate**：

- **客户端（给用户）**：6 个页签 —— 首页（五步向导）、预设、校准、BBS 预设、报告（占位）、设置。参数编辑器不再占页签，改由预设行右键「打开参数」以模态框进入（2026-10-09 的改判）。
- **发布端（工作台）**：生成预设产物、审计、发布事务（数据发布开 PR、软件版本发布走 Gitee Release）。整棵 `src/workbench/` 在 `feature="workbench"` 门内，**客户端二进制里搜不到任何 `wb_` 命令**。
- **内核**：`crates/preset`（预设读写/注册表/血统）、`crates/postprocess`（G-code 后处理）。后者目前**没有从客户端界面触发的入口**（见 `U-11`）。

### 3.2 一句话说清核心模型

用户世界里**只有一份可改可用的预设**（`presets-mine/`）；官方那一份是**只读模板**，住在内部数据根（下载区），只在三种情况下被引用：取回时校验、逐参数更新时提供「官方旧值 / 新值」、以及"当前使用"的另一条线。

```
官方源 ──目录(catalog)──┬─ 下载区 mkp/（内部字节，用户不可见）
                        └─ 云端表（用户看到"官方有什么、我要不要拿"）
                                    │ 取回
                                    ▼
                     presets-mine/（用户唯一能看到能改的那一份）
                                    │ 启用
                                    ▼
                     run/app-state.json#activePreset（只是一个指针）
```

关键事实：**「使用 / 启用」不复制文件、不生成对象，只写指针**（`apply_active_preset`，`ipc/catalog.rs::889`）。

### 3.4 六个"必须你拍板"的业务规则

1. **「使用」的入口放在哪**：现在首页、预设页、参数页三处都能改「当前使用」，且"选一份预设"就等于改底账（没有预览态）。
2. **官方旧字节（归档）要不要给用户看/删**：现在是"能看到 + 能删"，但它纯属官方版本生命周期。
3. **逐参数官方更新的默认路径**：现在是"打开参数 → 看到 N 项 → 逐项 adopt/hold"；建议默认收敛成"全部跟随 / 全部保持 + 想看才展开"。
4. **软件自更新是否进重写范围**：现在这条链只在工作台构建里注册，且只发 Gitee、只支持 macOS `.app.zip`。
5. **切片器那一档是否还在**：它有两套世界（预设页的切片器表 + BBS 参考页），且「复制到切片器」真机未接线。
6. **报告 / 后处理（`crates/postprocess`）是否进新版本**：现在界面上只是占位页，内核在仓库里但没有入口。

## 4. 审计边界与方法

### 4.1 追踪路径

对每个重要结论尽量建立这条链，并指明实际路径在哪一层断掉：

```
实际 UI 入口 → 事件处理函数 → 前端数据层 / Store → Tauri IPC 命令
            → Rust 实现 → 文件系统 / 网络 → 返回 DTO → UI 展示
```

不按函数名推断：同名命令、桥接映射、一次动作触发多条命令、异步与后台任务、文件写删改、内存与磁盘同步、错误与部分成功、同一事实的多处保存、开发/测试代码是否进正式产品、只有类型声明没有实现的东西——都逐条打开文件核对。

### 4.2 证据等级

| 等级 | 含义 | 本次条数（可自行在 HTML 里按此筛选核对） |
| --- | --- | --- |
| 已证实 | 追踪到实际实现，有代码位置或测试证据 | 绝大多数 |
| 部分证实 | 找到部分实现，完整调用链或运行结果未确认 | 少量 |
| 待验证 | 静态代码无法确定，需运行或观察 | 12 条（`unverified`） |
| 已发现冲突 | 代码 / 测试 / 文档 / 调用方之间有矛盾 | 10 条（`conflicts`）+ 5 条问题 |

“未发现”不等于“不存在”。本次用搜索 + 逐文件打开核对，但动态调用（拼命令名、事件名）与运行期分支仍可能有漏；`data/coverage.json` 里列了未覆盖范围。

### 4.3 本次**没有**做的事

- 没有跑 CI（web / rust / rust-windows 三个 job）。
- 没有起 Tauri 真机跑应用（结论停在代码层；所有"真机行为"都标了等级）。
- 没有逐函数审计 `crates/postprocess` 与 `crates/preset` 的内部实现。
- 没有逐动作清点工作台前端。
- 没有实跑 `cargo test` / `npm run build` 之外的产品行为验证。

详见 `data/coverage.json` 的 `notCovered` 与 `gaps`。
