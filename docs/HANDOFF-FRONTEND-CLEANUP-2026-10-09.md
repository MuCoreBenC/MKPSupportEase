## 0. 这次要做什么、不做什么

**做**：在现有前端上做「减法 + 纠错 + 解耦」。

1. 按**用户故事**盘点真实功能（看用户感知，不看实现细节），逐条裁断：**保留 / 保留但修错 / 删（假功能·死功能）/ 修好（接线）/ 待拍板**。

4. 报告页**保留**（占位照旧，本期不动）。

**不做**：

- 不重写、不换布局、不换导航结构、不换视觉。你习惯的界面就是目标界面。

- 不做假功能（纪律见 §6）。
- 不顺手改与清单无关的模块。

**分支**：在本仓库新建 `cleanup/preset-first`（名字可改），不碰 `feat/preset-param-official-update`。

## 3. 解耦方案（预设页为什么乱、怎么解开）

你说"改来改去已经很混乱"——审计把病根定位到了 5 个具体的耦合点，每个都有解法。**这一步是阶段 1b~1d 的施工内容。**

| # | 病根 | 现状 | 解法 |
| --- | --- | --- | --- |
| 1 | **行状态没有唯一权威** | 前端从 5 个读（catalog / downloaded / stale / trust / localFiles…）现场拼一行的状态和按钮判据（`src/app/presets/presetTree.ts::448` 起） | 状态判据收口成**一处**（一个模块 / 一个后端字段），页面只读不拼。改一处，处处一致 |
| 2 | **同一事实多套口径** | 「已下载」两套；状态词五套（四态/三态/MKP 三态/三档/两档） | 收成**两轴两词**：我这边有没有（没有/有/有但落后）× 官方有没有新的（没有/有） |
| 3 | **同一动作多词多入口** | 「应用/使用/使用它/下载并应用/更新」指同一两件事；入口散在首页、预设页、参数页 | 只留两个动词：**「取回」**（官方的拿到本机，幂等）与**「启用」**（设为当前使用，只写指针）。一个动词一个命令 |
| 4 | **一份文件两条编辑链** | 正文编辑（`putPresetDraft`）与参数编辑（`patchPresetDraft`）共用同一格草稿但语义两套（`src-tauri/src/ipc/mine.rs::351/374`） | 单草稿链：一份文件同一时刻只有一个未保存改动，保存只写一份 |
| 5 | **数据快照三份 + 错误被吞** | `usePresetData` / `usePreset` / `useCatalog` / `useParams` 各拉各的同一事实；31 处 catch 多处降级成空值 | 一层应用数据层（一个 store + 一个后端读）；三态显式（加载/失败/就绪），**失败和空长得不一样** |

**原则（每条改动都对照）**：

1. 判据只有一处：状态、按钮可用性、文案都从同一个地方出。
2. 用户看到的每个字都要能回答"我现在能不能用、要不要动手"；内部概念（血统 / baseline / 目录指纹 / 归档 / 事件账）不出现在主界面。
3. 一个动作一个词，一个词一个命令。
4. 看 ≠ 改：任何浏览动作都不许改底账。
5. 错误不吞：失败必须可见，不许用默认值/空值伪装正常。
6. **真机 IPC 走通才算实现**。mock 有实现不算（S3、S16、S24、S29、S8 全是这个坑）。
