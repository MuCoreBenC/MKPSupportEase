# 多版本「我的预设」与参数对比台（2026-10-08 作者裁决 · 实施记录）

> 作者原话（整理）：
>
> 「**不要'更新已有文件'，不要'三方合并'，不要判断用户到底应该更新哪一份。**
> 每次官方有新版本，就把它作为一个新的独立版本保存下来。用户自己决定怎么比较、怎么改。」
>
> 「**每次官方版本下载下来，就和第一次一样：一份官方基线 + 一份我的预设。**
> 只是以后再来新版，不覆盖旧的那一份。」
>
> 「你不应该从'怎么把官方新版合并进 Mine'出发，应该从'用户为什么要更新'出发。」
>
> 「baseline 是**隐藏的默认值来源** —— 它不是官方历史版本库给用户看的，
> 而是某一份'我的预设'所对应的官方原始数据，用来提供「恢复默认」的依据。」
>
> 「**对比台永远只对比用户自己的本地预设**；baseline 永远不进入用户视野。」
>
> 「**地址设置实时生效** —— 不允许要求重启。」

本文是这一版的**规格 + 实施记录**。它**取代**了此前两版方案
（"查看更新 + 三方 diff + 基于新版创建"，以及"官方历史快照库"）。
根规则（四层归属）见 [`DATA-ARCHITECTURE.md`](DATA-ARCHITECTURE.md)；
产品行为见 [`PRESET-PRODUCT-RULES.md`](PRESET-PRODUCT-RULES.md)（头部 2026-10-08 二次改判块）。

---

## 1. 一句话模型

```text
云端官方版本只负责产生新的「我的预设」；
baseline 是隐藏的默认值基准（系统内部，用户看不见）；
用户永远只操作自己的本地预设；
对比台永远只对比自己的本地预设；
baseline 永远不进入用户视野。
```

**没有**自动更新、**没有**三方合并、**没有**冲突状态、**没有**"过时文件"的生命周期管理。

---

## 2. 两个世界

### 用户世界：只有「我的预设」

```text
下载官方 V1  →  presets-mine/A1-fast-2026-10-08.toml
下载官方 V2  →  presets-mine/A1-fast-2026-10-15.toml      ← 多出一份新的；V1 那份一个字节不动
```

- 用户能看到的永远只有自己那份文件：可编辑 / 可改名 / 可删除 / 可应用 / 可复制；
- **"下载了一份官方预设" ≠ "拿到了一个官方版本对象"** —— 就是"我的列表里多了一份我的预设"；
- 旧的那份想删就删，删了之后用户层面就真的没有了（没有垃圾桶、没有归档）；
- 用户 UI 里**不出现**："官方历史版本"、"V1 已过时"、"官方快照"、"恢复到官方 V1"、
  "更新我的预设" —— 这些都没有。

### 系统内部：隐藏 baseline

```text
官方下载 V2026-10-15
        │
        ├── baseline/<sha256>.toml     ← 隐藏、只读、用户不可见
        │
        └── 我的预设  presets-mine/A1-fast-2026-10-15.toml
                      # based_on_sha256: <那个 sha>
```

`baseline/` 的规则（**逐条都是硬约束**）：

```text
· 用户不可见          · 不进入用户预设列表
· 不允许用户直接选择   · 不进入对比台
· 不提供删除按钮       · 不参与"新版本 / 过时"判断
· 不承担官方版本浏览   · 不需要用户理解
· 只供系统内部读取     · 主要用于「恢复默认」
· 同时作为 based_on_sha256 对应的原始基准
```

落点 = `<appDataDir>/baseline/<sha256>.toml`，**按内容摘要寻址**：摘要就是内容，于是
"幂等、每版一份、永不覆盖"在构造上成立，不需要任何版本生命周期管理，取回是 O(1)。
写入时机 = `delivery::deliver` 落 `catalog.path` 成功之后（`ensure_baseline`，失败只告警 ——
少了它只表现为"恢复默认"回退到出厂值）。

**不做垃圾回收**（作者原话：「文件就几个 KB，先保持简单。以后如果要做 GC，可以再单独做」）。

## 3. 日期：唯一的真值在文件头

- **已下载的那一版**：`# release_time`（`runtime::lineage::parse_release_time`）——
  这是"这是哪个官方版本"，**不是**"我什么时候拿到它"；
- 文件名 = `<官方原名的 stem>-<那个日期>.<后缀>`（`A1-fast.toml` + `2026-10-15` →
  `A1-fast-2026-10-15.toml`）。官方没写这一行就退回原名（**不编日期**）；
- 同日重名往后补 `-01` / `-02`（最多到 `-99`）；
- **不用**下载时刻 / 文件 mtime / Workbench 时间；
- **云端还没下载的那一版**拿不到它自己的发布日 —— 界面上只写「新版本」，
  时间列写**目录代时间**（`catalog.publishedAt`）并在 title 里如实标明是"目录发布时间"。
  **不做** `CatalogFile.releaseTime`、**不改** `gen-catalog`：不为 UI 上一个日期把契约扩散到上游。

---

## 4. 云端表：一个预设一组，版本各一行

```text
A1-fast
  2026-05-29   已下载          ← 已下载那一版（时间 = 它自己的 release_time 真值）
  2026-10-15   新版本  [下载]   ← 云端登记了、这一机还没下过的那一版
```

- 版本账来自 `runtime::versions`（当前目录 + 版本链 `archive/catalogs/*.json`，
  按内容摘要去重）；"下过没有"由 `runtime::baseline` 答（按摘要寻址）；
- **只列"下过的"与"当前那一版"**：下载命令认的是当前目录登记的那一条字节，
  历史版本没法按摘要重下 —— 列一行点了没反应的按钮比不列它更糟；
- **「新版本」的语义只有一句**：*云端有一个我还没下载的官方版本*。
  它**不是**"你那份过时了"，列表上也不会因此出现任何警示色。

## 5. 参数对比台（独立常驻工具）

**不是文本 diff、不是三方合并、不是"更新机制"。** 它是预设页工具条上一枚常驻按钮，
把 2~3 份**用户自己的本地预设**的参数并排摆出来：

```text
                    我的 A1 涂胶.toml        我的 A1 涂胶-2026-10-15.toml
Y 轴偏移  26.3 mm   [26.3]  采用此值          [26.8]  采用此值
Z 轴偏移  4.00 mm   [4.0 ]                   [4.0 ]
```

- **数据源只有「我的预设」** —— `baseline` 不进这张台子，台里也没有"只读列"；
- 每一格就是**参数页同款控件**（开关 / 数字 / 下拉 / 文本），可直接改；
  差异行整行高亮，值本身就是控件，不做"漂亮的文本 diff"；
- **「采用此值」是显式按钮**：把这一格的值复制到**本行其它几份**（按钮 title 里点名是哪几份）。
  不做"点一下某个值就神秘地把别处改了"那种手势；
- 保存各写各的：逐项走 `presetdata::patch::patch_preset_toml`（注释 / 键序 / inline table /
  多行字面量 / 行尾一个字节不动），任何一项失败**整批不落**；空改动不写盘。

命令面（`ipc::preset_params`）：`read_preset_params(path)`（只读，读不出来返回 `problem`
而不是抛错 —— 那一列如实说，不打掉整个框）、`save_preset_params(path, edits)`
（**只接受 `presets-mine/` 下的文件**）。

## 6. 参数页「恢复默认值」改基准

以前退回的是目录里的**出厂值**。现在是两档：

```text
有官方基准（这份我的预设当初那一版官方的默认值，从 baseline 取）→ 用它
没有（导入的 / 从用户预设复制出来的 / 血统缺摘要）        → 回退出厂值
```

命令是 `ipc::preset_baseline::get_preset_defaults(path)`（**只读**：只读用户那份的
**文件头**拿血统，再按摘要取 baseline）。基准里缺哪一项，那一项就回退出厂值
（参数表可能比当初那一版官方多出几项）。撤销栈与"算一次改动"的语义一个字不变。

---

## 7. 数据源地址实时生效

验收标准（作者原话）：**改完地址 → 保存 → 立即刷新数据源状态 → 下一次读取 / 检查就用新地址，
不允许要求重启。**

- 后端本来就每次现读（`runtime::source::resolve_source` 无进程内缓存）——
  `set_preset_source` 仍是"先探一次 catalog，通了才落盘"；
- 前端补的两件事：设置页保存成功广播 `sourceMutated()`（+ `deliveryMutated()`），
  预设页据此**复位"本次运行只检查一次"那道刹**并**按新地址重来一遍**
  （来源标签、后台检查目录、重读交付那一路）。

## 8. 本地官方源测试服务

> 「开发时，把'官方云端源'临时替换成本机 HTTP 服务。」

`scripts/preset-test-server/`（只用 `node:http` / `node:fs` / `node:crypto`，不进依赖树）：

| 命令 | 干什么 |
| --- | --- |
| `npm run preset-source:make` | 从**真交付根**派生 `fixtures/v1` 与 `fixtures/v2` 两代夹具（派生物不进版本库） |
| `npm run preset-source:sync` | 夹具里的 TOML 改过之后重算 `sha256` / `size` / `revision` |
| `npm run preset-source:dev` | 起服务（默认 `127.0.0.1:8787`，默认 `fixtures/v1`） |
| `npm run dev:test-update` | 夹具就绪 → 起服务 → 等就绪 → 以 `MKPSE_PRESET_SOURCE_URL` 起 `tauri dev` |

也可以从工作台起：**「设置 → 本地测试源（开发）」**那颗按钮跑的是
`npm run preset-source:dev`（`workbench/app/dev_source.rs`，起 / 停 / 查 + 清占用者）。
★ **它只起服务，不碰客户端**（作者 2026-10-08 裁决：「这不就是单开一个服务吗？
我自己输入这个地址就可以」）：地址由人填一次客户端的「设置 → 高级设置 → 预设数据源 →
自定义地址」（保存即生效）。那条"连客户端 dev 一起起"的便利留在命令行里 ——
`npm run dev:test-update`（它靠 `MKPSE_PRESET_SOURCE_URL` 注入，所以必须把客户端
dev 一起管起来）。

★ **端口被占着时先把占用者摆出来、问一句**（2026-10-08 踩出来的）：8787 上已经有东西
（上一轮留下的服务、你手动起的一份）时这一份起不来 —— 原来是让它撞死、界面上只留一句
"退出码 1"。现在起之前先探那个端口，把占用者（进程名 + PID）连同那句人话交出来，
界面列出来并给一颗「停掉它」（`wb_dev_source_clear_conflict`，**先验明正身再动手**：
重新问一次"这个端口现在还是它的吗"，PID 对不上就拒绝）。

判据是**端口**而不是命令行：进程的命令行 / 工作目录在某些环境里读不到（本机实测
`sysinfo` 对所有进程都返回空），拿它做判据会变成"按钮点了没反应"；端口是硬事实 ——
谁在听 `netstat` / `lsof` 说得出来，`taskkill` 停得掉（旧项目
`mkppanel/presets_server.go` 的 `ListOccupiedPorts` / `StopPortProcess` 就是这一套）。

`MKPSE_PRESET_SOURCE_URL` 的覆盖点在 `runtime/source.rs::current_entry` 最前面，
**`#[cfg(debug_assertions)]`**：release 里这段代码整个不存在，
`check-release-source.mjs` 与"启动零网络"两条判据都不受影响。
客户端**不感知这是测试源** —— 它仍走 catalog / manifest / 寻址 / SHA 校验 / 下载管道。

## 9. 命令面与落点（本轮）

| 命令 | 干什么 |
| --- | --- |
| `get_official_versions(fileName?)` | 官方版本账：每版 `releaseTime`（已下载时是真值）/ `publishedAt` / `downloaded` / `current` |
| `get_preset_defaults(path)` | 「恢复默认」的基准值（`values: null` = 没有基准） |
| `read_preset_params(path)` | 读一份我的预设的参数（控件形态的字符串） |
| `save_preset_params(path, edits)` | 结构保真写回它自己（只认 `presets-mine/`） |

新增模块：`runtime/baseline.rs`（存储）、`runtime/versions.rs`（版本账）、
`presetdata/params.rs`（抽值 / 批量保真写）、`ipc/preset_baseline.rs`、`ipc/preset_params.rs`。
改动的既有模块：`runtime/delivery.rs`（落盘后 `ensure_baseline`）、`runtime/mine.rs`
（`ensure_working_copy` 按官方发布日命名）、`runtime/source.rs`（debug 源覆盖）、
`runtime/lineage.rs`（`parse_release_time`）。

---

## 10. 边界（本轮明确不做）

- **不做自动更新 / 三方合并 / 冲突消解**：连概念一起退场；
- **不做 `CatalogFile.releaseTime`、不改 `gen-catalog`**：不把 UI 需求扩散到发布侧；
- **不做 baseline 的垃圾回收**；
- **不做数据迁移**：换命名 / 换路径一律当全新应用，旧目录由用户自己删；
- **`catalog.path` 不动**：它仍是当前官方版本的唯一 URL 锚与下载落点；
  归档（`archive/`）也照旧只服务交付四态判定 —— 与 baseline 是两件事。
