# 需求：SupportEase 修改 MKP 参数后，使 Bambu Studio 当前切片结果失效

**日期：** 2026-10-15
**状态：** 待技术验证

## 1. 目标

SupportEase 管理 XYZ 偏移、涂胶等 MKP 后处理参数。这些参数保存在 SupportEase 自己的 TOML 文件中，不属于 Bambu Studio（BBS）原生切片参数。

当用户修改并保存这些参数后，需要使 BBS 当前板子的上一次切片结果失效，让用户能够直接在当前 BBS 窗口中再次点击「切片」。

本需求的核心是：

**将 SupportEase 的参数变更，连接到 BBS 内部已有的切片结果失效机制。**

不是让 SupportEase 自己重新切片，而是让 BBS 允许用户重新发起切片。

## 2. 目标流程

1. 用户在 SupportEase 修改 XYZ 偏移，例如将 X 从 `0.00` 改为 `0.20`。
2. SupportEase 成功保存新的 MKP TOML。
3. SupportEase 通知失效处理机制：当前 BBS 的上一次切片结果需要重新验证。
4. BBS 内部切片有效性状态被正确更新。
5. 用户回到当前 BBS 窗口，「切片」按钮变为可用。
6. 用户点击「切片」，由 BBS 自己重新计算，并正常触发 MKP 后处理钩子。

整个流程必须保留当前打开的模型、板子、打印机、耗材和其他切片设置。

## 3. 必须遵守的边界

- 不启动另一个 BBS 进程来代替用户切片。
- 不调用 CLI 重新生成 G-code。
- 不自行重跑 MKP 内核来伪装成重新切片。
- 不要求用户重新导入模型。
- 不通过切换预设版本实现失效。
- 不删除、移动、改名或修改磁盘上的旧 G-code 来试图刷新状态。
- 不修改用户实际需要保留的板子类型、耗材、打印机或工艺参数。
- 不把后处理成功与否当成切片有效性状态的替代品。

## 4. 技术调查任务

### 任务 A：查明 BBS 的真实失效机制

针对当前安装版本 Bambu Studio `02.08.02.60`，检查对应版本源码或可验证的二进制行为。

重点调查：

- `PartPlate::update_slice_result_valid_state(...)`
- `PartPlate::is_slice_result_valid()`
- `MainFrame::get_enable_slice_status()`
- `Plater::update_background_process(...)`
- `Print::invalidate_all_steps()` 及相关失效状态传播机制
- 「切片」按钮从禁用变为启用的完整调用链

以上是调查入口，不预设它们在当前安装版本中的具体实现与调用关系。

明确区分：
1. 切片步骤是否失效；
2. 当前板子的切片结果是否有效；
3. 「切片」按钮是否启用；
4. 后台切片任务是否正在运行。

不要将这几个状态混为一谈。

### 任务 B：寻找可由 SupportEase 触发的入口

按优先级调查：

1. BBS 是否存在官方 API、扩展点或进程间通信接口，可以让当前窗口将指定板子的切片结果标记为无效。
2. 如果没有公开接口，是否存在不修改 BBS 安装包、也不注入或篡改进程内存的受支持调用路径。
3. 如果仍然没有，评估 macOS UI 自动化能否通过一次安全、可恢复的操作触发同一套失效机制。

不得假设修改配置文件就会让 BBS 重读配置或更新内存状态。

不得只搜索函数名。必须核对当前版本中的真实调用链、状态更新条件，以及「切片」按钮启用的判定逻辑。

### 任务 C：验证最小实验

先不要修改 SupportEase 正式业务代码。

建立可重复的验证步骤：

1. 打开模型并完成一次切片。
2. 确认切片完成后按钮处于禁用状态。
3. 修改 SupportEase 的一个 XYZ 偏移并保存。
4. 仅触发候选失效机制。
5. 检查同一个 BBS 窗口中，当前板子的切片结果是否失效、按钮是否启用。
6. 点击「切片」，确认原生切片任务启动，并能再次调用 MKP 后处理钩子。
7. 检查模型、板子、预设及其他配置没有发生非预期变化。

分别验证参数真正发生变化、重复保存相同数值、切片任务运行中修改参数等情况，避免不必要的失效或状态错乱。

## 5. 验收标准

**唯一硬判据：** 修改并保存 SupportEase 的 XYZ 偏移后，在不手动修改 BBS 参数、不重新导入模型、不启动新切片器进程的情况下，当前 BBS 窗口的「切片」按钮恢复可用。

点击后由 BBS 原生执行切片，并能正常进入后处理流程。

如果当前 BBS 版本没有可靠的外部触发路径，必须明确报告技术限制与证据，不得通过假成功、隐藏的重新切片或破坏用户配置来满足验收。

- 哪种入口可以真正触发失效；
- 该入口是否适用于当前安装版本；
