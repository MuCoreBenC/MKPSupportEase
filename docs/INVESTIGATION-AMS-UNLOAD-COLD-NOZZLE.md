# 调查：AMS 退料卡在 30 °C（校准件打完不结束）

> 2026-11-26。现场是一台 A1 mini + bMCU（AMS lite 协议）。
> 结论先行：**不是切刀切不动，是退料那一段根本没开始加热** —— 校准件先把喷头目标温度压到了 30 °C。

## 1. 现场

| 项 | 内容 |
| --- | --- |
| 产物 | `60636.0_20261126_191215.gcode`（Z 偏移校准件，2 层，A1 mini） |
| 现象 | 模型打完、挂笔校准跑完，机器停在原地：屏幕只有一个「加热中」，温度停在 30 °C 不动 |
| 进度 | 停在 **2%** |
| 告警 | **没有**任何弹窗（尤其没有「切刀卡住」） |

**2% 不是真实进度。** 校准音乐块自带 `M73 P0 R2` / `M73 P1 R2` / `M73 P2 R2`（产物 4431 / 4443 / 4453 行），把进度条拨回了 0/1/2%、剩余时间改成 2 分钟。模型本身早就打到 100% 了。

## 2. 结论

机器自己的收尾段里有这一段：

```text
; pull back filament to AMS
M620 S255
G1 X181 F12000
T255
G1 X0 F18000
G1 X-13.0 F3000
G1 X0 F18000 ; wipe
M621 S255
```

它是「切料 → 挤出 → 回抽」，整段要在**热态喷嘴**下才走得完。而校准块在这之前做了：

```text
; Calibration Runtime: retract and cool down
G92 E0
G1 E-2.0 F1800
G92 E0
M104 S30          ← 目标温度 30 °C
```

`M104` 不阻塞，所以屏幕不会停在降温上；但目标已经变成 30，固件进 `M620 S255` 时拿到的就是一个「按 30 度算已经到温」的喷嘴 —— 于是停在加热等待，`M620.11` 切料**还没开始**。这解释了为什么没有切刀告警（那条告警要求刀柄压下后两分钟不回弹）。

`M104 S0 ; turn off hotend` 在 4494 行，排在退料之后 —— 也就是说整个退料期间，喷头目标一直是 30。

**为什么不接 AMS 时没事**：外挂盘没有 AMS，`M620 S255 / T255` 是空转，机器没有料要退、没有丝要切，收尾照常走完。

**为什么普通模型没事**：同日 19:29 的普通模型 `35088.0_20261126_192904.gcode` 全文没有 `M104 S30`，走到 `M620 S255` 时喷头仍是 245（最后一条温控是 `M104 S245`）。

## 3. 官方依据

1. **Bambu Wiki「Replacing filament」(P1)**：点 Unload 之后 —
   `The printer will begin heating up the hot end, then cutting the filament automatically.`
   `https://wiki.bambulab.com/en/p1/manual/replacing-filament`
2. **AMS 卸载说明**：`The printer will heat the nozzle, cut the filament, and the AMS will retract it back onto the spool.`
3. **切刀卡住（`0300800B` / `HMS_0700-4500-0002-0003`）**：切刀由工具头移动压刀柄，刀柄带磁铁、由进料霍尔判断回弹；刀柄两分钟不回弹才告警。
   `https://wiki.bambulab.com/zh/hmscode/0300800B-cutter-is-stuck`
4. **A1 技术规格**：工具头切刀内置。`https://bambulab.cn/zh-cn/a1/tech-specs`

由此可知：退料是「先加热 → 再切 → 再抽回」。加热服务的是切后那一段挤出与回抽（冷料挤不动），不是刀片本身。

## 4. 代码落点

| 位置 | 作用 |
| --- | --- |
| `crates/postprocess/src/postproc/calibration.rs:292` 起 | 校准块的插入点选择与降温块（`M104 S30`） |
| `crates/postprocess/src/postproc/disk/calibration.rs:520` 起 | 校准块尾：`;Toolhead Unmounted` + 结束音乐 + `G1 X100 Y100 Z100`，无温度恢复 |
| 机器自带 `machine_end_gcode` | 收尾段；`; pull back filament to AMS` ~ `M621 S255` 就是退料 |

降温本身是必须的：喷嘴不降到 30 会一直滴料，挂笔与浮动 Z 校准都会脏。

## 5. 处置

新增客户端偏好 **「打完退料」**（`PrefsIr::ams_unload_after_print`，出厂 **关**）：

- **关（出厂）**：收尾段里 `; pull back filament to AMS` ~ `M621 S255` 整段不写。机器不走退料，也就没有加热等待，耗材留在喷头里。
- **开**：保留退料段；**校准件会把整块校准挪到退料之后** —— 模型刚打完、喷头还是 245 时先把料退完，再抬 Z、`G28 X Y` 归零（退料后工具头停在右侧切料位，不归零挂不上笔），然后才降温做校准。

两条规矩：

- 认不出 `M621 S255` 或找不到起点注释 ⇒ 整段不动。只删 `M620 S255` 或 `T255` 会把收尾改坏。
- 开关对普通模型与校准件同时生效；普通模型本来就在热态退料，开与关只差「退不退」。

## 6. 真机验收

1. **零代码确认**：卡在 30 度时从屏幕或 Studio 把喷嘴设到 240。若机器立刻继续退料并走完收尾 ⇒ 诊断成立。
2. **开关关**：重打同一块校准板，收尾应直接跳到结束音乐与 `M73 P100 R0`，没有任何「加热中」停留；耗材留在喷头。
3. **开关开**：重打同一块校准板，顺序应为「模型打完 → 立刻退料（此时还热）→ 回零 → 降温 → 挂笔校准 → 收尾」。

## 7. 推论边界

- 「固件在 `M620 S255` 里等的是温度」是推论：现场只能看到「加热中 + 温度不动 + 无告警」。第 6 节第 1 条是判定它的唯一实验。
- 没有验证 bMCU 侧在退料时的应答时序；若补温后仍卡，下一步该查这里，而不是继续往 G-code 里加指令。
- 不同机型模板的段内指令不完全一样（P1S 的切料位是 `G1 X267`），所以识别只用两个锚点：注释头 `; pull back filament to AMS` 与段尾 `M621 S255`。
