# 预设事件时间模型（Preset Event Time Model）

- 日期：2026-10-06
- 性质：**设计与实现说明**。本篇把 `PRESET-TIME-SEMANTICS.md` 的梳理结论重新定义为一个小而明确的事件系统，并描述它如今的实现。
- 后端：`src-tauri/src/runtime/preset_events.rs`（模型与账本）+ `delivery.rs`（写事件、版本身份反查、建账 bootstrap）
- 前端：`src/api/contract.ts`（事件时间的 DTO）+ `presetTree.ts` / `PresetTable.tsx` / `PagePresets.tsx`（只显示，不解释）

---

## 0. 这是什么、不是什么

**是一个事件时间系统**：凡是界面上要"永久解释"的时间，先定义它属于哪个事件；事件发生那一刻把时刻定格进账。

**不是**：

- 不是一个大账本 —— 不记录软件的所有操作，只记"未来 UI / 业务需要解释的历史事实"；
- 不是通用事件总线 —— 只服务预设系统（`preset_events`），不做全 App 的通用事件系统；
- 不做通用事件信封 —— 没有 actor / context / metadata / previous / next，**每个事件只带自己需要的字段**。

核心动机（此前的三个观感矛盾，全部源于 mtime 被派了业务用场 + "云端现在"顶了"它当时"）：

1. 「下载时间 10:13 比云端更新 13:46 还早」—— 两个字段属于两个版本，但没说清；
2. 「旧版本的时间居然是现在」—— 归档 mtime（= 你点「更新」那一刻）顶在唯一的时间位上；
3. 「云端有更新了它就显示云端的」—— 本机这份的详情里，"云端最新版"被当成了"你这份的云端时间"。

---

## 1. 三条硬规则

1. **一个事件只能有一个语义。** 不许一个 `modifiedUnix` 今天叫下载时间、明天叫归档时间。mtime 从此只回答"这个文件系统对象最后什么时候被改"，不再承担任何业务语义。
2. **事件发生时定格。** `at` 写进账之后，云端换代、文件挪动、再次扫描，都不能改变它。账只追加，不回写。
3. **没发生过 / 不知道，就没有。** 读侧给 `null`，界面写「未知」。**禁止** `downloadedAt ?? file.mtime` 这种猜。

---

## 2. 五个事件与各自的记法

| 事件 | 语义（一个事件一个语义） | 记法 |
|---|---|---|
| `ReleasePublished` | 这一代目录在云端发布的时刻 | **不落账**：发布侧盖进目录的 `publishedAt`，随目录字节与版本链（`archive/catalogs/`）走到每台客户端，按字节指纹反查（`delivery::generation_index`） |
| `DeliveryDownloaded` | 这份字节第一次落进本机 | **落账** `preset_events.json`：`{ file, sha256, revision, at }` |
| `DeliveryReplaced` | 这份字节换掉了盘上的旧份（旧份进归档、新份落盘的同一刻） | **落账**：`{ file, oldSha256, oldRevision?, newSha256?, newRevision?, at }` |
| `MineModified` | 我的文件最后一次保存 | **不落账**：按作者裁决就是文件系统 mtime —— 声明在此，免得它再被派别的用场 |
| `ProvenanceRecorded` | 复制 / 导入的出处 | 已有自己的账（`provenance.json`），不动 |

**事件的键是字节，不是路径**：`sha256` 进了事件，同一份文件换过几版就有几条各自的事件。路径（`file` = catalog `files[].path`）只是定位符。

一条 `DeliveryReplaced` 同时解释两侧、各答各的格子，互不顶替：

- 归档里那份旧字节（`old_sha256`）的**替换时间** = `at`；
- 盘上这份新字节（`new_sha256`）的**到位时间**也是 `at`。

---

## 3. 写侧：事件在哪里定格

唯一咽喉点 = `delivery::deliver()`（取回 → SHA/大小校验 → 防穿越 → 归档旧份 → 原子落盘）。写盘成功的那一刻：

- 盘上原本没有 → `DeliveryDownloaded`；
- 旧份被换掉（`is_update`）→ `DeliveryReplaced`（旧份属于哪代目录，趁它还在盘上查一把，查不出就 `null`）；
- 同字节重放 → **什么都没发生，不记事件**。

记不上不影响下载本身（附加信息，与 `provenance.json` 同一条口径）。

## 4. 存量建账（bootstrap，一次性）

账文件（`<appDataDir>/preset_events.json`）不存在时，第一次读事件账把盘上存量记进来（`delivery::load_events`）：

- **归档区先记**：每份旧字节一条 `DeliveryReplaced`，`at` = 归档文件的 mtime —— 这不是猜：归档是原子写新文件（`fsx::atomic_write`），写它的那一刻就是换版那一刻；
- **下载区后记**：只记**认得出出身**（SHA 对得上某代目录）且**来历还没被替换事件解释过**的字节，`at` = 文件 mtime；同一份盘上字节只有一种来路（硬规则①）—— 被替换事件解释过的不再记「下载」；
- **认不出的字节不记**（被改过 / 链之前的）—— 界面照实「未知」，不许 mtime 冒充业务时间（硬规则③）。

建过账之后只追加（`preset_events::append`），任何人都不再回写。

## 5. 读侧：UI 拿到什么

UI 拿到的都是**点名的字段**，不需要知道背后是 mtime、catalog.json、版本链还是事件账：

| UI 位置 | 字段 | 事件来源 |
|---|---|---|
| 本地交付行「时间」列 + 详情第一格 | `downloadedUnix` / `replacedUnix`（标签跟着事件走：「下载时间」/「替换时间」） | 账（至多一个有值；都没有 = 认不出，照实「未知」） |
| 本地交付行详情「本机这份发布于」 | `ownPublishedAt`（仅当认得出且与云端最新**不是同一代**时显示） | `ReleasePublished` 反查（跟着这一版字节走，云端换代不变） |
| 本地交付行详情「云端最新版发布于」/「云端最新版本」 | `publishedAt` / `releaseVersion` | 当前目录（名字里带「最新」，不再被读成"你这份的"） |
| 云端表「云端更新」列 | `releaseAt` | 当前目录（这里说"云端现在"是**对的**） |
| 旧版本抽屉每条 | `publishedAt`（云端发布）+ `replacedUnix`（替换时间） | 反查 + 账；查不到照实「未知（早于版本记忆）」 |
| 我的文件「修改时间」 | `modifiedUnix` | 文件系统 mtime（按裁决） |

**归档条目再也不给 mtime**（DTO 字段已换成 `sha256` / `publishedAt` / `replacedUnix`）—— "我动它的时刻"不再冒充版本时间，两个时间同屏：

```text
云端发布  2026-10-06 13:46      ← 这一版是什么时候发的
替换时间  2026-10-06 16:34      ← 它是什么时候被换下来的
```

## 6. 顺带修掉的两件事

- **归档清单泄漏**：`archived_files` 此前会扫到 `archive/catalog.json` 与版本链 `archive/catalogs/*.json` —— 那些是**版本记忆**（换下来的是"目录"，不是"旧份"），现在明确排除；
- **版本出身的"最早登记"规则**：同一份字节在几代目录里都登记过时（收回重发），以**最早**登记它的那一代为它的发布（版本的出生，不是它最近一次被提起）—— 各代目录按 mtime 从旧到新排序后取第一命中。

## 7. 刻意不做的

- **`ArchiveDeleted` 不记**：删除还没有入口（归档"不删不恢复"是现状）。等删除放开时再决定记不记 —— 事件系统不要求"所有操作必须记录"，只要求"需要解释的历史事实统一从事件来"；
- **不做事件查询语言 / 回放 / 订阅**：读侧就两个查找（按 file+sha 找到位、按 file+old_sha 找替换），够用；
- **不让 `ReleasePublished` 落账**：发布时刻的权威在发布侧，客户端存一份就是第二真相源。

## 8. 以后加行为时（恢复 / 重新下载 / 删除 / 重新导入）

不会再出现"这个时间该拿哪个字段"的问题 —— 先定义事件（例如 `DeliveryRedownloaded`、`ArchiveDeleted`），在动作发生的那一刻定格，UI 需要解释就加一格显示，不需要就只留事实在账上。
