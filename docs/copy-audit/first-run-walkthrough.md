# 首次使用摸底（只看截图的 AI 跑的第一遍）

> 规则照 `docs/UX-SCENARIO-TEST.md`：只读界面上看得见的字，不读代码、不猜实现，
> 需要猜就记「需要猜」，30 秒找不到下一步就记「说不出来」。
>
> **这一遍是基线**：文案还没改，所以它记的是「在说明还在的情况下，人能不能自己找到路」。
> 文案落地之后要再跑一遍，两遍对比才知道删掉的说明是不是真多余。

## 一、任务 1：把 `A1-fastv3.3.toml` 更新到最新

| 我要做什么 | 我以为会发生什么 | 实际看到的 | 判断 |
| --- | --- | --- | --- |
| 让这一份用上云端最新版 | 找「更新」按钮，点了就开始更新 | 这一行左边写「已是最新（云端发布前进过…）」，右边却有一颗绿色的「更新」 | **矛盾**：既然已是最新，为什么还能更新？不知道该不该点 |
| 确认它到底是不是最新 | 看一个明确的状态词 | 同一句话在三个地方出现：行里、展开后右上角、右侧「更新状态」 | **重复**：读完三遍还是不知道结论 |
| 判断「有没有变过」 | 看「判定」 | 「判定 / 内容没变」 | **需要猜**：判定的是什么？内容没变为什么还给「更新」？ |
| 想知道「什么时候变的」 | 找一个时间 | 表头「目录发布 11-10」、详情「云端更新 2026-11-10 20:06」、详情「云端新版发布 2026-11-10 20:06」 | **三个时间，三种说法**，分不清哪个代表内容变过 |
| 想确认来源 | 看「来源」 | 「云端 · feat/postproc-notice-hero」 | **看不懂**：`feat/` 是分支名，用户不知道它是什么，也不知道要不要在意 |
| 看到底部那串哈希 | 以为是版本号 | 「云端最新版本 b46d1963c6e59ee5」 | **需要猜**：这串能不能点、要不要记 |

**这一步的结论**：能点，但点之前不确定结果。可预测性不及格。

## 二、任务 2：下载还没下载的那一份

| 我要做什么 | 我以为会发生什么 | 实际看到的 | 判断 |
| --- | --- | --- | --- |
| 装一份新的 | 点行尾「下载」 | 第三行「未获取」+ 黑色「下载」 | **可以**：这是全页最清楚的一处 |
| 下载完去哪儿找 | 下载后能直接用 | 没下载过，看不到后续；页脚只提了右键菜单 | **说不出来**：下载后是进「本地」表还是留在这张表，界面没有交代 |
| 不想下载、只想看看内容 | 点行展开 | 第一行没有按钮，也没有明显的提示说「点行展开」 | **不可发现**：行本身可点，但看不出来 |
| 找更多操作 | 页脚说右键 | 「右键任意一行还有 下载 / 更新 / 复制链接」 | **犹豫**：行里已经有「更新」，右键里又有「更新」，哪个是正路？ |

**这一步的结论**：主路径可走；「下载之后会怎样」「行能不能点」两处靠猜。

## 三、任务 3：删掉一份已经放进切片器的配置

| 我要做什么 | 我以为会发生什么 | 实际看到的 | 判断 |
| --- | --- | --- | --- |
| 删掉 `MKPProcess A1 0.4 0.20.json` | 先找到删除入口 | 行尾只有「已放入」，没有删除；删除在右键菜单里 | **说不出来**：不右键就找不到删除 |
| 确认删的后果 | 知道会不会丢 | 标题「删除 …？」，正文第一句「它回到「未下载」，随时可以从云端重新下载」 | **矛盾**：叫「删除」，结果只是「回到未下载」——那到底删了什么？ |
| 判断要不要勾复选框 | 知道「切片器目录里那份」指哪个 | 「同时删掉切片器目录里那份」 | **说不出来**：本机有几个账号目录？哪一个是这一份？界面上没有 |
| 判断勾了会不会白勾 | 勾了就该彻底没了 | 说明里写「BBS 已经把它同步到你的账号云端的话，下次打开 BBS 会再拉回来」 | **无法判断**：不知道自己有没有同步过，也不知道勾它还有没有意义 |
| 判断「正在使用」 | 知道现在是不是在用 | 这一行写「已放入」，正文写「正在被使用的话，会一并撤下」 | **术语不一致**：放入 / 使用，是一个意思吗？ |

**这一步的结论**：主按钮清楚，但三个前置判断（删的是什么、勾的是什么、会不会被拉回来）都靠猜。

## 四、五维评分（只针对这一页）

| 维度 | 分 | 理由 |
| --- | --- | --- |
| 可发现性 | 2 / 5 | 「下载」看得见；「更新 vs 已是最新」分不清；删除藏在右键 |
| 可理解性 | 2 / 5 | 判定 / 来源分支 / 哈希 / 目录发布，四个词都要内部知识 |
| 可预测性 | 2 / 5 | 点「更新」前不知道会问什么、会不会动文件 |
| 可恢复性 | 3 / 5 | 正文提了「可重新下载」「最近删除」，但埋在长句里 |
| 连续性 | 2 / 5 | 同一事实三个时间、三种说法，用户要自己拼 |

## 五、说不出来的地方（这一节是重点）

1. **「已是最新」旁边为什么有「更新」**——状态与动作互相打脸。
2. **「判定 / 内容没变」到底是什么判定**——是内容，是版本，还是来源？
3. **三个时间哪个算数**——目录发布 / 云端更新 / 云端新版发布。
4. **`feat/postproc-notice-hero` 要不要看**——用户不知道分支是什么。
5. **哈希能干什么**——不能点、不能复制（看不出来能复制）、也不知道该不该记。
6. **「共 3 项 · 云端 8 · 本地 4」**——三个数对不上，不知道 3 是什么的范围。
7. **第一行没有按钮**——是已完成、是禁用、还是要点开才有操作？
8. **下载之后去哪儿**——留在云端表还是进本地表？
9. **删除到底删什么**——叫删除，正文说回到未下载。
10. **复选框指哪一份**——切片器目录有几个、这一份在里面吗？
11. **勾了会不会被 BBS 拉回来**——拉回来那还勾什么？
12. **「放入」和「使用」是不是一回事**。

## 六、这些点里，哪些不是改字能解决的

| 问题 | 归类 | 说明 |
| --- | --- | --- |
| 状态与动作打架 | 文案 + 规则 | 改字能缓解（状态说「内容没变 · 可重新下载」），但「更新」按钮该不该出现在这一行，是规则问题 |
| 同一事实说三遍 | 布局 | 行、详情顶部、更新状态各一处；要留哪一处得看版面能承载什么 |
| 三个时间并列 | 布局 | 要么合并成一个「内容更新于」，要么分层（主时间 + 折叠里的两个） |
| 行没有按钮 | 布局 | 可点却看不出来；要么给一个常驻动作，要么给可点的视觉线索 |
| 删除入口只在右键 | 布局 | 与页脚那串枚举是同一个病：菜单不可见，只能靠文字补 |
| 「放入 / 使用」两套词 | 文案 | 可统一，属改字能解决 |
| 复选框指代不清 | 文案 + 布局 | 文案能写清「本机 2 个账号目录」，但完整答案要靠列表 |
