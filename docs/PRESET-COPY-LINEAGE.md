## 0. 作者要什么（原话）

> "是谁出来的，他就跟随着谁的机型和版本呀。"
> "官方的完全也可以复制出来呀，就是另存为一份出来呀。"
> "我这个没修改，直接保存出来的，跟这个一样的呀。"

两条：

1. **官方交付那份，应当能「另存为一份新的」** —— 现在「另存为一份新的」只在"我的文件"之间开放，官方行灰掉，tooltip 让人"走「改这份」→ 保存"。可"改了再保存"与"不改直接复制"落的是**同一种东西**（截图证据：不改一个字直接保存出来的那份，与官方那份内容一致）——绕一道编辑流程才能复制，不合直觉。
2. **复制/另存出来的那一份，机型与版本跟着来源走** —— 现在用户文件的两列写死「—」、名称列挂「未标机型」，可展开详情里明明写着"基于 A1 mini · 快拆版6月以前 · 官方当前版"。**同一份身世，详情里有、列上没有** —— 这就是不合理本身。

## 2. 设计原则：身世随来源

一份用户文件的**身份**由它"从哪来"回答，显示与筛选都从这一身份推导。三类来路，三条规则：

| 来路 | 机型 / 版本 | 来源格 | 记账 |
|---|---|---|---|
| **官方交付 → 另存** | 来源交付文件登记的 `machineId / versionId` | "复制自 官方 X"（血统三行） | 血统写进文件头；出处账**不重复记**（既有口径：官方另存的出处走血统） |
| **我的文件 → 另存**（现状保留） | 与来源那份**显示的**一样（递归继承） | "复制自 直接来源"（出处账，可点定位） | 按字节复制、血统原样带过去 + 出处账记 `copy`（既有） |
| **外部导入**（现状保留） | 没有身世 → 「—」+「未标机型」，不猜 | "导入" | 出处账记 `import`（既有） |

**用户显式标注永远压过继承**：身世是**默认值，不是锁**。今天还没有"标注适用机型"的入口（代码注释原话："机型这一层根本没有来源，今天没有地方让用户标它"）——等那个入口出现时，用户标的算他的话；没标的时候，身世说话。

副本可以继续被另存（链式）：mine → mine 按字节复制时血统原样带过去，所以"副本的副本"的机型/版本仍然跟着**官方原始来源**走；直接来源由出处账单独记（两格各说各的事，与事件时间模型同一套"一格一语义"的规矩）。

## 3. 交互设计

### 3.1 「另存为一份新的」对官方交付行放开

- **适用范围**：release 行且 `releaseState === 'ok'`（字节可信才能复制 —— 旧版本 / 内容异常的禁令**不变**，与"不许应用、不许改"同一条边界：我们不认的字节不能换个名字继续活着）。
- **后端**：新增命令 `copy_release_as_new(file_name, new_name)`：
  - 从下载区取**已验证的那份字节**（SHA 与目录一致才叫 ok）；
  - 写进 `presets-mine/<new_name>`，文件头**新写血统三行**，`based_on` 指向来源交付文件（catalog 身份 + 它的发布时刻）——官方原件本身没有血统头（它是源头），所以这里不是"照抄来源的 based_on"，而是"指向来源"；
  - 名字冲突 / 空名 / 非法字符的处理与 `copy_as_new` 同一套；
  - 出处账不记（血统已经答了"从哪来"）。
  - **能复用就复用**：`commit_preset_draft` 的"保存为用户文件"已经会写血统三行 —— 这条命令基本是"不改一个字的同一条路"，抽公共函数，别长第二套写法。
- **前端**：`copyWhyNot` 放行 `origin === 'release' && releaseState === 'ok'`；复用现有"另存为一份新的"输入框（我的行的同一条流程）；成功 toast + 重读用户线；tooltip 改说"复制到你的目录，身世（机型/版本/来源）跟着它走"。
- 官方**仓库行**（切片器 profile、图标等 `origin === 'official'`）**不在这一批**：它们不是 TOML 预设，"另存"无从谈起。

### 3.2 机型 / 版本列继承（显示层回退，第一刀最小实现）

`UserPresetFileDto` 已经带着 `basedOnMachineId / basedOnVersionId` —— **后端不用动**，前端 mine 分支改取值顺序：

```text
用户显式标注（暂无入口） > 血统（based_on 的机型/版本，显示名按目录查） > 「—」+「未标机型」
```

- 列上：有血统 → 显示机型名 / 版本名（与官方行同一条 `versionName` 查名路）；都没有 → 维持「—」与角标；
- 「未标机型」角标只在**连血统也没有**时挂 —— 有身世的不许再被说成"未标"；
- **机型筛选**：带血统的行归到它继承的机型档下（选 A1 mini 能看到它，「全部机型」也能）；认不出身世的行维持现状（任何机型档下都列 —— "藏起来等于说他没这份文件"）；
- 顶部计数（`仓库 9 · 本机 0 + 我的 1`）口径跟着核对：mine 行进入机型档后，按机型计数的统计要走同一套继承值。

### 3.3 「修改 → 保存」出的那份

与 3.1 同一条路（血统已写）—— 3.2 落地后**自动**继承机型/版本，不需要第二套代码。作者截图里那份"A1_MINI-fast（已修改）.toml"到时就显示 A1 mini / 快拆版6月以前。

## 4. 数据与边界

- **身世的三个来源**（优先级从高到低）：用户显式标注 > 血统/出处账 > 无。每一格只答一个问题，不混（与事件时间模型同一条规矩）；
- **血统认不出的旧形状**（`basedOnSource === unknown`，老文件记的旧路径）→ 列回退「—」，不回填、不猜（既有口径）；
- **改名 / 删除 / 重新下载**：血统在文件头里跟着文件走，改名不影响；mine 文件删除后出处账条目悬空、界面照实退回（既有 `provenance.rs` 的规矩）；
- **时间**：另存/复制不产生新的时间事件（出处账的 `at` 已记时刻；`DeliveryDownloaded` 管的是官方字节，与用户副本无关）；
- 官方交付文件本身**不带血统头**（它是源头）—— 另存出的副本才有。
