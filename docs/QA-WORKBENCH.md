# 工作台 · 用户故事走查清单

> 协议见 `docs/UX-SCENARIO-TEST.md`：**只看界面、不看代码**，从处境出发，记录卡在哪。
> 这里只列工作台这一侧的故事与判据；机械断言那一半在 `scripts/qa/`。

## 怎么跑

1. `npm run dev:workbench`，浏览器开 `http://localhost:5322/workbench.html?mock=1`
   （`?mock=1` 是假后端；真机数据要用 `npm run tauri:workbench:dev`）。
2. 一次只给代理**一个故事**，不给实现提示。
3. 每条故事的产出：走了几步、卡在哪、界面原话、「需要猜」之处、截图。
4. 结论并入 `npm run qa` 的报告（观察行），不判红 —— 红/不红由机械断言管。

## 故事（每次至少跑前 5 条）

| # | 处境（只说这个） | 该记录什么 |
|---|---|---|
| 1 | 「我想把回抽长度挪到回填长度前面」 | 找到排序入口用了几步；能不能一次看清整组 |
| 2 | 「我把一条参数放错分组了，想搬回去」 | 搬完之后它在目标组的哪一位，符不符合预期 |
| 3 | 「我改错了一条参数的说明，想退回原样」 | 会不会误按「保存」；「放弃」在哪、说不说得清 |
| 4 | 「我给这组新建一个分组，把这组两条参数搬进去」 | 新建后能不能立刻选中；取消保存后有没有残留 |
| 5 | 「我不知道这条参数什么时候才生效」 | 「前置条件 / 属于 / 档位」看得懂吗 |
| 6 | 「这条参数我不想再用了，但历史值要留着」 | 找到「弃用」用了几步；看不看得出它影响谁 |
| 7 | 「换了台机型，刚才那份改动还在不在」 | 有没有"改到一半切走就丢"的惊 |
| 8 | 「我想知道这次改了哪些东西」 | 页头「已保存 · 查看改动」找得到吗 |

## 计分（每个故事 1-5）

可发现性 / 可理解性 / 效率 / 容错 / 一致性 —— 与 `UX-SCENARIO-TEST.md` 同一套，
不要另发明维度。

## 判红的边界

同一个故事里出现下列任一情况，**同时**记进机械断言（能脚本化的就脚本化）：

- 点了没反应；
- 报错文案里出现内部词（字段名、`params.layout` 这种）；
- 关掉重开之后状态对不上；
- 需要退回去重来才能完成（一次做成不了）。
