# 界面文字规范（客户端）

> **只管文字**：小字、说明、副标题、状态句、提示、通知、tooltip、确认框。
> 间距 / 组件 / 布局看 `DESIGN-SPACING.md`；文案住在 `src/i18n/{zh-CN,en,zh-TW,ja}.ts`，
> 四本字典一起改，`npm run check:i18n` 是闸。

## 0. 一句话

**文字只补布局说不清的那一点。读完这句，用户没有多知道一件事，就删。**

判据不是「说得对不对」，是「删掉它，用户会不会做错」。不会，就删。

## 1. 三条铁律

1. **一处只说一次。** 同一件事在行状态、详情、提示条里各说一遍，等于三处都在喊。
   保留用户做决定时看的那一处，其余删。
2. **说明只讲后果，不讲机制。** 「删了会回到未下载、可以重新下载」是后果；
   「云端那份一直留着，不会丢什么」「BBS 已同步到账号云端」是机制。
   机制只允许出现在折叠区或 tooltip。
3. **布局优先。** 能用位置、分组、对齐说明的关系，不写句子。
   写说明之前先问：这是不是布局没排好？（页脚把右键菜单十几项列一遍，就是布局欠账。）

## 2. 写之前先过四问

| 问 | 不合格就 |
| --- | --- |
| 删掉它，用户会做错吗？ | 不会 ⇒ 删 |
| 它在解释软件内部怎么运作吗？ | 是 ⇒ 删，或只进折叠区 |
| 同一事实这一屏说了几次？ | 大于 1 ⇒ 留一处 |
| 用户此刻需要它吗？ | 不需要 ⇒ 挪到他需要的那一刻（tooltip / 折叠 / 出错时） |

## 3. 位置与字数（硬指标）

| 位置 | 上限 | 合格例 | 不合格例 |
| --- | --- | --- | --- |
| 主按钮 / 动作 | 4 字 | 更新、放入、使用、删除 | 重新从云端下载 |
| 列表状态词 | 8 字 | 已是最新、有新版本、未下载 | 已是最新（云端发布前进过…） |
| 行内副标题 | 12 字 | A1 · 0.4 喷嘴 | 这是工作台生成的那一份 |
| 一组一条的说明句 | 30 字（1 句） | 改动会写回这份文件。 | 换完立刻生效，记在应用状态里 —— 下次打开还是这一档。 |
| 提示条 | 40 字（1 行） | 有改动没保存。 | 刚才那些改动还没保存、还没生效 —— 要生效得先保存 |
| 确认框正文 | 2 句 / 60 字 | 删除后回到未下载，可以重新下载。正在使用的会停用。 | 它回到「未下载」，随时可以从云端重新下载（云端那份一直留着，不会丢什么）… |
| 复选框说明 | 1 句 / 40 字 | 同时删除切片器里的同名文件。 | 删的是本机那几个账号目录里的同名文件。BBS 已经把它同步到… |
| tooltip | 50 字，只答「点了会怎样」 | 更新：先让你挑云端改过的参数 | 更新状态说明：这一格表示… |
| 错误句 | 40 字：发生了什么 + 下一步 | 没删成：文件被占用 | 删除失败：{detail} |

一条说明只能有一句。分号、「——」、括号都是第二句的伪装。

## 4. 禁用写法（反例 → 正例）

| 写法 | 反例 | 正例 |
| --- | --- | --- |
| **括号补丁** | 随时可以从云端重新下载（云端那份一直留着，不会丢什么） | 可以重新下载 |
| **破折号补机制** | 已复制出一份：x —— 原文件一个字都没动 | 已复制 x |
| **安抚尾巴** | 随时、一直、不会丢什么、一个字都没动、照样 | 删 |
| **双重否定 / 排除句** | 这不是你这台机器的问题，也不是加载失败 | 机型没有可用版本 |
| **旧白话** | 这一份 / 那一份 / 对得上的那一份 | 这份 / 它 / 对应的那份 |
| **「的话」** | 它正在被使用的话，会一并撤下 | 正在使用的会停用 |
| **字段名当句子** | 本机暂无副本，下载后建立基线再判定 | 本机没有，下载后才知道新旧 |
| **元话术**（谈软件自己） | 连不上时如实说没查到，不冒充「已是最新」 | 连不上，没查到新版本 |
| **三件套堆一行** | 来源：github · main · 第 12 版 · 2026-11-06 | 第 12 版 · 11 月 6 日（分支进折叠区） |
| **英文直译腔** | 你复制出来的那一份是独立的一份 | 副本是独立的 |
| **重复陈述** | 行状态说「已是最新」，详情再说「已是最新（长句）」，顶部再说一次 | 只留行状态 |
| **说明代偿** | 页脚：右键任意一行还有使用 / 复制 / 修改 / 编辑 / 对比 / 重命名… | 菜单里能看见，页脚只留一句「右键看更多」 |

## 5. 内部概念 → 用户话

只改说法，不删字段。字段该在还在，词换成用户能读的。

| 内部说法 | zh-CN | zh-TW | ja | en |
| --- | --- | --- | --- | --- |
| 发布序号 / publishSerial | 第 {n} 版 | 第 {n} 版 | 第{n}版 | Version {n} |
| 目录发布 | 云端发布 | 雲端發布 | クラウド公開 | Published |
| 云端发布线 / 来源发布线 | 发布线 | 發布線 | 公開ライン | Release line |
| 基线 / 本机留档 | 本机这份 / 本机记录 | 本機這份 / 本機記錄 | この端末の記録 | This copy |
| 判定 / 版本判定 | 版本 | 版本 | バージョン | Version |
| 补齐字段 | 补齐信息 | 補齊資訊 | 情報を補完 | Fill in details |
| 归档 | 旧版本 | 舊版本 | 旧バージョン | Older version |
| 溯源记录 | 来源记录 | 來源記錄 | 入手元の記録 | Origin |
| 发布身份 | 发布编号 | 發布編號 | リリース ID | Release ID |
| SHA-256 / 摘要 | 指纹 | 指紋 | ハッシュ | Fingerprint |
| 交付文件 | 云端文件 | 雲端檔案 | クラウドのファイル | Cloud file |
| 归属 | 机型 / 版本 | 機型 / 版本 | 機種 / バージョン | Machine / variant |

专名不译：机型名、版本名、文件名、`BBS`、`3MF`、`G-code`、`MKP`。

## 6. 状态句模板

- 列表：`<状态>` 或 `<状态> · <一个动作>`。例：`已是最新` / `有新版本 · 更新` / `未下载 · 下载`。
- 状态只有四档：`未下载`、`已是最新`、`有新版本`、`本机副本`。别的都要落进这四档。
- 详情可以多一句「为什么」，≤20 字，且**不得复述行状态**。
- 说不清新旧就不说：`无法确认`，不给「更新」按钮。

## 7. 动作词

- 动词开头，说结果：`下载`、`更新`、`放入`、`使用`、`停止使用`、`删除`。
- 同一动作全站同名，不换同义词（更新 ≠ 升级 ≠ 拉到最新）。
- 破坏性动作直说：`删除`、`停用`，不用「清理 / 移除」混着叫。

## 8. 确认框模板

```text
标题：<动作><对象>？            删除「A1 0.4 0.20」？
正文：<后果 1 句><影响 1 句>     删除后回到未下载，可以重新下载。正在使用的会停用。
选项：<一句，说清范围>           同时删除切片器里的同名文件。
按钮：取消 | <动作>（红）
```

- 机制（BBS 同步、归档目录、账号目录）最多进复选框说明，一行说完。
- 「可找回」要写清去哪找：`设置 → 最近删除`。

## 9. 回执与错误

- 成功：`已<动作> <对象>`，最多加一个「· 下一步」。不解释规则、不安抚。
- 失败：`没<做成什么>：<原因>`，能重试就给重试。原因来自后端就用后端那句，不要另编一句。
- 不用感叹号，不用「哦 / 啦 / 呢」。

## 10. 四语规则

- 一条键四本字典同改（`zh-CN` / `zh-TW` / `ja` / `en`），占位符集合一致，`check:i18n` 必须绿。
- 行内长度：英 ≈ 中 × 1.4，日 ≈ 中 × 1.2；超了就砍信息，不换行。
- `zh-TW` 用台湾用字（預設 / 設定 / 檔案）；`ja` 用です・ます；`en` 用 sentence case、动词开头、不用 `Please`。
- 标点：中文用「」，英文用引号；不在句末堆「…」。

## 11. 改一条文案的流程

1. 用 §2 四问判断它该不该存在（该删的直接删，别润色）。
2. 套 §6–§9 的模板。
3. 查 §5 换术语。
4. 四语一起写。
5. `npm run check:i18n`，再跑 `npm run check:copy` —— 后者只查描述位（`.note` / `.hint` /
   `.tip` / `.title` / `.desc` / `.subtitle`）的破折号补解释、括号补丁、超 40 字、
   安抚话术与内部说法。它已挂进 `npm run lint` 与预推钩子。
6. 用 §12 自检。

## 12. 交稿前八问

1. 删掉这句，用户会做错吗？
2. 这一屏同一件事说了几遍？
3. 有没有括号 / 破折号在解释机制？
4. 有没有字段名直接当句子用？
5. 一句话是不是超过了 30 字？
6. 状态词落进那四档了吗？
7. 确认框写的是后果，还是流程？
8. 四语都写了、占位符都齐吗？

## 13. 边界

- 本规范**不管布局**。控件太挤、层级不清、页脚枚举菜单这类问题，
  记进 `docs/copy-audit/` 对应页的「布局建议」栏，另行处理，不靠改字糊过去。
- 参数名 / 参数说明是数据（`presets/registry/param_registry.toml`），不在这张表里。
- 后端渲染的句子在 `crates/postprocess/messages.toml`，同样四语，同一套写法。
- `src/workbench/**` 是开发台，不在本规范范围内。
