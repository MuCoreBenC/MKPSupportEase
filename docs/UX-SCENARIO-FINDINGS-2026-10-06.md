## A1 官方预设复制：三层拆开

**用户发生了什么**：右键官方文件 →"另存为一份新的"灰掉，提示"官方那份的副本走
「改这份」→ 保存（会另存成你自己的一份）"→ 照提示去找，**官方文件的详情面板里没有
「改这份」**→ 摸到参数页编辑器 → 确认框说"以下 1 处改动将写入 A1mini-standard.toml"、
没有副本选项 → 不敢赌，取消。任务失败。

1. **正路存在但指针扑空（真缺陷）。** 设计上的复制正路 = 交付行展开详情里的
   「改这份」→ 编辑器 →「保存为用户文件」（`scripts/probes/presets.mjs` §5e 验过
   `A1-standard.toml` 有这个按钮）。但禁用项的提示只说"走「改这份」"，不说它在哪、
   什么条件下才有；用户照提示走会扑空。悬停 title 本身也只有悬停才看得见（B2）。
2. **这条正路被文件健康状态钳制（设计如此，但呈现方式可议）。** 内容存疑的官方文件
   （演示数据里 A1 mini 的标准版恰好是"内容异常"档）没有「改这份」——守的是"改的来源
   必须是官方当前版"。守卫本身成立；问题是用户拿着一份"官方"文件却处处碰壁时，界面
   没有一处把"为什么这份不行、哪份行"说齐。
3. **两处保存口径互相矛盾（真缺陷，最重的一条）。** 预设页右键提示说官方文件改完
   保存"会另存成你自己的一份"；参数页编辑器却说"保存后会覆盖 A1mini-standard.toml"。
   两个编辑器是两条管道（预设页行内编辑 = 临时文件另存；参数页 = 校准偏移写回当前
   版本的文件），但用户看到的都是"编辑这个预设 → 保存"，措辞相反，只能靠赌。
   A 级里最该先修的是这一条措辞。

## A2 失败提示：一半真缺陷，一半环境

- **真缺陷**：`NO_ASSET_WHY`（`presetTree.ts:214`）——"你自己放进预设目录的文件仓库里
  没有记录，没有 asset id —— 而契约的 applyPreset / copyToSlicer 只认 asset id。
  给一个点了必报错的按钮比不给糟"。这段话是写给开发者的：术语、还有一句开发者牢骚。
  它会在真实状态到达用户（用户真往 `mkp/` 放一份来路不明的 toml 时，就是这个文案）。
  更糟的是它对文件的描述在测试场景里是**错的**：那份 `A1MF_260628.toml` 是演示资产库
  里登记在案的官方文件，不是用户放的——文案把两种状态混用了一句话。
- **测试提前撞线的缝（演示数据）**：这个文案的调用点本该"到不了"
  （`PagePresets.tsx:889-892` 注释原话"到不了这里：MKP 档的本地表只有交付行有操作按钮"），
  但演示数据里 `A1MF_260628.toml` 是**旧资产库**的行（有 assetId、无 releaseUid，
  `assets.json` 里 MKP 预设仍以 asset 形式存在；新世界"MKP 不进资产库"见
  `presetTree.ts:1163`）——旧行形状走出了本该不可达的按钮分支，点下去就撞上这段话。
  真机不该走到；但"理论不可达的守卫带着开发者文案、且演示环境一踩就到"这件事本身
  值得收掉。
- **环境边界（不算产品缺陷）**："未实现的接口: downloadCatalogFile / deleteDeliveryFile"
  一类是浏览器 mock 如实拒。但它们暴露一个模式：`errorText()` 把 API 层原文直接亮给
  用户。真机上等价场景（IPC 报错冒泡）也会这样——**错误文案的人话化是一层系统性缺口，
  不是一句话的事**。

## A3 "正在使用的预设"两处矛盾：架构缝

预设页横幅读**唯一底账**（`run/active-preset.json`，应用时写入）；首页设备卡的
"预设文件 A1F.toml"读的是**向导自己的机型/版本选中态对应的目录登记文件**
（`PageHome.tsx:248-256`，按 `sel` 从 `catalog.presets` 反查，不读底账）。两个概念都
自称"现在用的预设"，数据源不同，真机上同样会分叉（应用了一份"我的"文件之后必分叉）。
`PagePresets.tsx` 的注释（"动作认 fileName … = 首页反填要读的那一条"）说明设计意图是
两边同源——实现没对上。**这是三条 A 里唯一的纯架构问题，也是用户信心被打破的直接来源。**

## B 级里值得单独说的

- **B8（修改时间语义）**：测试原话——"版本号、列表时间、修改时间是同一天，我分不清
  修改时间是官方发布日还是落盘日"。这正是 `PRESET-EVENT-TIME-MODEL` / `PRESET-TIME-SEMANTICS`
  在设计的事：**模型已经落了，界面词汇还没跟上**。下一轮改界面时把"发布于 / 下载于 /
  改于"三个词用起来，这条就消了。
- **B11（机型列）**：用户文件"机型=未标机型"，但同屏详情里就有"基于 A1 · FAST"。
  数据里有 `basedOnMachineId`（应用时也写进底账），列表却没用它——出身已经收账，
  "给哪台机器用"这一格是白捡的。
- **B10（两处云端日期打架）**：具体数值是演示数据两处演示值没对齐（`publishedAt`
  演示值 vs 目录 modified 演示值）；但"同一份文件两处各说一个'云端时间'、标签还不一样"
  是真实的呈现问题，时间词汇统一时一并收。
- **B6（2.0 KB → 216 B）**：演示种子的假大小 vs 保存后按真字节算出的大小，纯演示缝。
  真机两端都是真值，不算缺陷。
- **B12（role="dialog" 缺失）不成立**：共享 Modal（`Modal.tsx:150`）、选择预设抽屉
  （`PresetPickerDrawer.tsx:85`）、参数页三个确认框（`PageParams.tsx:1002/1028/1060`）
  都有 `role="dialog"`，历史探针也一直按 role 定位成功。测试代理的困难来自遮罩拦截
  （=B4）而非语义缺失。保留 B4，撤 B12。

## 测试代理的终局回答（原话摘要）

> **如果你是一个真实用户，你会不会觉得这个软件在和你作对？**
> 前半小时会，后面不会。第一天最想干的两件事——"装一份官方预设"和"复制一份官方预设
> 自己改"——每条路都堵死，报错还全是天书……但一旦改用"我自己的文件"，体验急转……
> 它更像一个对"自己的东西"尽心、对"官方的东西"层层设防、又在失败时词不达意的软件
> ——防备有余、沟通不足。

> **如果只能改三处？**
> ① 报错文案人话化（发生了什么 + 能做什么）；② 给官方预设一条"另存为我的副本"正路，
> 统一保存口径；③ 统一"正在使用的预设"真相源，抽屉随页面切换自动关闭。

做得好的（测试代理列的，原样保留）：删除流程的诚实（故事 7 全程最高分）；文件出身与
谱系的解释质量（详情/正文/归档三处，故事 4、9）；保存自己副本后的三重可验证反馈

## 故事 3：看中一份官方预设，想保留原版不动，同时有一份自己的副本
- 实际路径：

## 汇总：四档问题清单

### A 真正阻碍使用的问题
1. **官方预设没有任何"复制成我的副本"的可行路径**（故事 3）。右键"另存为一份新的"禁用（悬停提示指向官方文件上根本不存在的「改这份」按钮）、"在 Finder 中显示"禁用、云端右键菜单无复制项、详情面板无相关按钮、"应用/更新/下载"全部报错。想"保留原版+一份自己的副本"的用户在界面里无路可走，只能放弃或绕行（改用自己的旧文件凑合）。
2. **失败提示全部是开发者口吻**（故事 1、6、8）："你自己放进预设目录的文件仓库里没有记录，没有 asset id —— 而契约的 applyPreset / copyToSlicer 只认 asset id。给一个点了必报错的按钮比不给糟"；"更新失败：[API] 未实现的接口: downloadCatalogFile"；"尚未实现：downloadFiles（A1M.toml）"；"没删成：[API] 未实现的接口: deleteDeliveryFile"。失败后界面没有告诉我：这是我的问题、网络问题还是软件没做完；下一步该干什么（换一份？去设置里配数据源？等修复？）完全无从判断。失败高发（下载/应用/更新/删官方文件四类操作都失败），所以这不是偶发边角。
3. **"正在使用的预设"两处显示互相矛盾**（故事 10）：预设页顶部横幅"已应用 我的 A1 涂胶.toml · A1 · 我的文件"，首页设备卡片"预设文件 A1F.toml"。同一时刻两个答案，用户无法确认哪份配置真正生效，"我应用成功了"的信心被直接打折。

### B 轻微别扭的问题
1. "需更新 1 份"（状态文字）与"更新 1 份"（执行按钮）一字之差、外观相近、行为完全不同，我把它当筛选点了，结果直接触发一次批量下载（故事 6）。
2. 禁用菜单项的说明只存在于悬停 title 里，且指向的替代路径在官方文件上不存在——照着提示走会扑空（故事 3）。
3. 编辑器数值输入后不登记改动（底部仍显示"没有未保存的改动"、保存按钮仍禁用），要失焦才生效，界面无任何说明（故事 3）。
4. "旧版本"抽屉切标签页不自动关闭，遮罩持续压暗整页，底下按钮看得见点不着；页面上同时存在多个"×"（提示条的、抽屉的），我关错了两次（故事 10）。
5. 还原草稿的提示拗口难懂："草稿没写进磁盘：现在没有正在改的那一份，改不了参数"；且历史里已还原的条目仍标"未保存"（故事 8）。
6. 保存后文件大小 2.0 KB → 216 B，对比前后正文内容没有丢失，但那 1.8 KB 去哪了没有任何解释（故事 5）。
7. 本地列表"来源=官方"的文件，报错却说"你自己放进预设目录的文件"——标签与报错互相矛盾（故事 1/2）。
8. "修改时间"语义不明：同一文件的"版本日期、列表时间、修改时间"常是同一天，分不清是官方发布日还是落盘到我电脑的日子（故事 2）。
9. "复制到切片器目录"成功后列表无任何变化、没有任何去处可核对，只能信一条提示（故事 8）。
10. 同一文件两处日期不一致：详情"云端更新 2026-10-05 16:00" vs 归档"云端发布 2026-10-06 13:46"（故事 9）。
11. 我的文件"机型=未标机型 —"：出身（基于 A1）讲清楚了，适用哪台机器却不标（故事 2/4）。
12. 确认框/抽屉没有 role="dialog" 等语义标记，屏幕阅读器用户难以感知弹层（测试中按 role 查找多次扑空）。
13. 搜索只匹配文件名；没有"最近保存/最近修改"入口，不记得文件名就找不回（故事 10）。

### C 纯视觉问题
1. 右侧设备面板超出版视口被裁掉一半（首页 shot-001、shot-064 均如此）。
2. 抽屉内说明长段落贴着右边缘排，视觉拥挤、局部有裁切感（shot-057）。
3. 顶部同时存在提示条 + 抽屉 + 两个"×"时，视觉层级混乱（shot-062）。

### D 不是问题、无需修改
1. 删除确认框"这是你自己的文件，删了就没了 —— 程序没有垃圾桶、也没有归档（删掉就是真删掉）"——看似吓人，实则最诚实的写法，配合删除后"真删除，没有留档"的二次确认，用户不会误解（故事 7）。
2. 官方文件右键菜单大量禁用项——保护官方原件不被误改/误删的设计意图成立，且每项都有解释性提示（虽然提示可读性另说，见 B2）（故事 3）。
3. "应用"后按钮变"已应用"+顶部横幅全局更新——状态外显的好设计（故事 10）。
4. 搜索即输即筛、无延迟无按钮（故事 10）。
5. 行内详情展开代替弹窗，不打断列表上下文（故事 2）。
6. "看正文"里对文件归属的大白话解释（"官方换版本不会动它；改它写回的是它自己"）——把最容易误解的事一次讲清（故事 4/9）。
7. 失败提示"浏览器里没有下载区，也没有数据源地址"这类带人话后半句的（故事 6）——虽然前半句仍是术语。

## 终局问题
- **如果你是一个真实用户，你会不会觉得这个软件在和你作对？**
  前半小时会，后面不会。第一天最想干的两件事——"装一份官方预设"和"复制一份官方预设自己改"——每条路都堵死，报错还全是天书，那一刻确实觉得它在和我作对（"给一个点了必报错的按钮比不给糟"这种话出现在我的屏幕上，感觉像误入了开发者的聊天记录）。但一旦改用"我自己的文件"，体验急转：出处写得明明白白、保存可三重验证、删除诚实到把"没有垃圾桶"提前告诉我。它更像一个对"自己的东西"尽心、对"官方的东西"层层设防、又在失败时词不达意的软件——防备有余、沟通不足。
- **如果只能改三处，你改哪三处？**
  1) 全部报错文案翻译成人话：删掉 asset id / API 接口名 / 开发者牢骚，每条错误给出"发生了什么 + 我现在能做什么"。
  2) 给官方预设一条正路"另存为我自己的副本"（右键可用或详情页加按钮），并统一保存口径——别让菜单提示说"会另存成你自己的一份"、编辑器却说"会覆盖官方文件"。
  3) 统一"正在使用的预设"这一处真相：首页设备卡与预设页"已应用"必须同源同步；顺手让抽屉随页面切换自动关闭。
- **这次体验里做得好的地方（至少 3 条）**
  1. 删除流程的诚实（确认框+结果提示两处把"真删、无档"讲透，故事 7）。
  2. 文件出身与谱系的解释质量（详情"基于 A1 · FAST · 官方已换新版"、正文大白话、归档说明"官方生命周期 vs 你的修改历史"，故事 4/9）。
  3. 保存我自己的副本后的可验证性（提示条、列表时间、正文内容三处一致，故事 5）。
  4. 搜索的即时与准确（故事 10）。
  5. 行内展开详情、全局"已应用"横幅等不打断上下文的状态设计（故事 2/10）。
