# 日志

三件事：**记什么**、**留多久**、**怎么交出去**。

## 三条流

落点都在 `<内部根>/logs/`（macOS：`~/Library/Application Support/<标识符>/logs/`）。

| 文件 | 谁写 | 级别 | 记什么 |
|---|---|---|---|
| `supportease.log.<日期>` | 界面进程 | release `warn`，debug `info`（`SUPPORTEASE_LOG` 可覆盖） | 启动、数据根、命令失败、发布链 |
| `ui.log.<日期>` | 界面进程（前端 `track()`） | 恒 `info` | 点击、切页、开关、弹框开关、每次命令结果 |
| `hook.log.<日期>` | 钩子进程 | 恒 `info` | 后处理那一趟：输入、预设、走到哪一步、什么码、退出码 |

`ui` 是**单独的 target**：应用日志压到 `warn` 是为了不让它一天涨几十 MB，而点击恰好是高频低价值 ——
把整体提到 `info` 两头都输。两条流各配一层过滤器（应用日志 `ui=off`，交互日志只收 `ui`）。

### `ui.log` 记什么、不记什么

- 记：按钮点击（`data-track` → `aria-label` → 可见文案）、页签切换、开关翻转、弹框开关、
  主题 / 语言 / 更新渠道的切换、更新区那枚插画翻转、每次后端命令的成功与失败（失败带错误码与 `traceId`）。
- 不记：hover、滚动、鼠标移动、输入框里的字。这些量级会把真因埋掉。

一次点击打出来的七八条命令是同一个批次（400 ms / 64 条一批），日志里靠时间相邻读得出来。

## 留多久

按天滚动，**14 天 + 三流合计 20 MiB 双限**，谁先超就从最旧的删（`obs::rotation`）。

三条不删：今天那一份（正在写）、每条流最新的一份（停用半个月回来，最后一次还在）、不认的文件。

触发点：启动后一次（后台线程）+ 进程内 24 小时节流（`log_ui_events` 顺手判一次，长会话不靠重启收敛）。

设置页那个「自动清理」**只管执行记录**（`gcode_history` 三件套），与日志无关。

## 交给开发者

设置页 →「数据与维护」→「导出日志」：一个 zip，默认落桌面。

```
summary.txt                 版本 / 构建指纹 / 系统 / 数据根 / 语言与主题 / 日志日期范围
logs/supportease.log.<日期>
logs/ui.log.<日期>
logs/hook.log.<日期>
```

脱敏（逐行、打包那一刻真做过）：

- 家目录与用户名 → `~`（Windows 的反斜杠与正斜杠两种写法都认）
- IPv4 / IPv6 → `x.x.x.x` / `[x:x::x]`（端口留着 —— 排查要认哪个口没通）
- 不含预设文件、3MF、G-code、`app-state.json` 原文

保留：预设名、机型名、错误码、命令名 —— 抹掉它们等于把要查的东西抹掉。

没有日志可导时如实报 `E_LOG_EXPORT_002`，不产空包。

## 按 `traceId` 捞一次调用

界面上每条错误都带 `traceId`（uuid v7，前 48 位是毫秒时间戳，按字典序排 = 按时间排）。
`grep <traceId> logs/*` 能把那一次调用的 span 与失败原因整段捞出来。

## 命令

| 命令 | 用途 |
|---|---|
| `log_ui_events` | 前端批量写交互记录（前端不直接摸 tracing） |
| `log_export_plan` | 读清单：哪几份、多大、覆盖哪几天（不打包） |
| `default_log_dir` | 导出默认落点（桌面；问不到退数据根 `exports/`） |
| `export_logs` | 打包 |
| `reveal_log_export` | 在文件管理器里选中那份 zip |

错误码：`E_LOG_EXPORT_001` 打包失败 / `E_LOG_EXPORT_002` 没有日志 / `E_LOG_EXPORT_003` 目标位置写不进。
