## 1. 结论（三句）

1. **G-code 里没有「喷嘴压到模型」或「平移撞到模型」的路径错误。**
   全文件按几何扫三遍，模型区（X<160）**一处都没有**出现「喷嘴 Z ≤ 该点已打印材料高度」，
   8mm 半径的横向干涉也是 0（唯一命中是 X=256 的工具头停靠位，那里没有模型）。
2. **层高不是固定的**（`_original.gcode` 与成品 `Z_HEIGHT` 序列 `diff` 零输出 ⇒ 不是 MKP 加的）：
   基准 `0.278`，在**支撑接触面**区间自动变细到 `0.2`，变化处插 `0.006~0.19` 的过渡碎层（见 §4.1）。
   46mm 落在 `0.2744` 的**厚层段中部**，不在薄层/过渡区。
   塔的 Z 实测跟着层 Z 走（滞后 0~0.28），`Safe Z` 够用 ⇒ **塔不是嫌疑**（见 §4.2）。
3. **「涂胶落笔压深 0.2mm」是误读，不是 bug。** 落笔用的是 `last_layer_height`（上一层层顶），
   实测与公式完全对齐（见 §3）。

## 3. 「落笔压深 0.2mm」是误读（已排除）

原始怀疑：`;MKP_BEGIN paint ev=52 z=38.8` 后面落笔 `G1 Z42.5`，按
`层顶 + glue_z_offset + offset_z = 38.8 − 0.05 + 3.95 = 42.70` 算对不上，差 0.2。

实际公式（`crates/postprocess/src/postproc/pass1/glue_block.rs`）：

```text
glue_pen_z(layer_z, Landed)    = layer_z + glue.z_offset        // -0.05
glue_nozzle_z(layer_z, Landed) = glue_pen_z + toolhead.z_offset // 3.95
调用处传的是 last_layer_height（上一层层顶），不是 current_layer_height
```

对齐两份实测：

| 涂胶块 | `paint z=`（当前层） | 上一层层顶 | 落笔 `G1 Z` | 公式 |
| --- | --- | --- | --- | --- |
| ev=1 | 0.6 | 0.4 | **4.3** | 0.4 − 0.05 + 3.95 = 4.30 ✓ |
| ev=52 | 38.8 | 38.6 | **42.5** | 38.6 − 0.05 + 3.95 = 42.50 ✓ |

涂胶发生在**当前层开始之前**，此时已打印面就是上一层层顶，笔尖 = 层顶 − 0.05，
即「压进 0.05」—— 与 `PenZ::Landed` 的注释一致。**没有偏差。**

⚠️ 读日志时别把 `paint z=`（current）与落笔 `G1 Z`（last）按字面配对，会凭空造出 0.15–0.25 的假差值。

## 4. 层高：不是固定的，但**不是 MKP 改的**

### 4.0 切片器自己写下的参数（`_original.gcode` 的 `CONFIG_BLOCK`）

```text
; layer_height = 0.2                 ← 基础层高
; initial_layer_print_height = 0.2
; enable_support_ironing = 1          ← 支撑界面熨烫（开）
; support_ironing_pattern = concentric
; support_ironing_flow = 15%
; support_ironing_spacing = 0.3
; support_ironing_speed = 70
; support_interface_top_layers = 1
; support_top_z_distance = 0          ← 支撑与模型**零间隙**
; support_style = grid
; support_type = normal(auto)
; z_hop = 0.4                         ← 跨墙抬升只有 0.4
; z_hop_types = Auto Lift
; reduce_crossing_wall = 0            ← ★「避免跨越外墙」是**关**的
; ironing_type = no ironing           ← 模型本身不熨烫（熨的是支撑）
```

### 4.1 事实：层高不是固定的，但**不是 MKP 改的**

`_original.gcode`（切片器原文，`Tower_Layer_Gcode`/`MKP_BEGIN`/`Pre-glue` 各 0 处）与成品的
`Z_HEIGHT` 序列 **`diff` 零输出** ⇒ 层高完全来自切片器。

段表（`_original.gcode` 实测，只列 ≥3 层的段）：

| 类型 | Z 区间 | 段内层高 |
| --- | --- | --- |
| 薄 | 0.4–4.4 / 12.4–16.2 / 25.4–27.4 / 38.8–41.0 / 52.8–53.8 | **0.2** |
| 薄 | 65.6–70.0 / 76.2–79.8 / 89.6–92.0 / 94.4–95.8 / 102.0–104.0 | **0.2** |
| 薄 | 111.4–113.2 / 118.4–120.2 / 131.8–134.8 / 136.8–141.0 | **0.2** |
| 厚 | 上述之间的空档 | **0.2695 – 0.2788** |
| 碎 | 每次切换的前后 | 0.0061 / 0.0207 / 0.0276 / 0.0364 / 0.0424 / 0.0483 / 0.052 / 0.057 / 0.0727 / 0.0759 … |

**两类东西要分开，之前混成一种了**：

1. **碎 Z（0.0759 / 0.1241 / 0.0483 …）= 支撑熨烫层**（作者说对了）。
   实证：`Z_HEIGHT: 4.47586` 那一整层只有 `; FEATURE: Support`、`; LAYER_HEIGHT: 0.0758619`，
   `G3 Z4.8 → G1 Z4.476` 落到支撑顶面再熨一遍。层号照常 +1（`23/1064`），所以它**是真的新层**，
   只是打的是支撑不是模型。`support_top_z_distance = 0` + `enable_support_ironing = 1` 是它的来源。
2. **厚 0.2744 段 = 真层高**，不是熨烫。
   实证：45.19–47.39 每层 `E` 总量 2.24–3.54、路径 57–83mm、53–64 段，与别的层同量级；
   熨烫层不可能有这么大的挤出量。

⇒ **`layer_height = 0.2` 写在 config 里，实际却按段跑到 0.2744**。
能同时满足「config 是 0.2」「切片后按段变 0.27x」「不进 `different_settings_to_system`」的只有一项：
**可变层高 / 高度范围修饰器**（它们是模型级设置，不写进 gcode 的 config 块）。
作者截图里的「自适应 · 细节速度 0.50 · 平滑 半径 5」就是**可变层高对话框**，请对照确认。

★ **薄层段与 MKP 的涂胶段 100% 重合**（0.6–4.4 / 12.4–16.2 / 25.4–27.4 / 38.8–41.0 / 52.8–53.8 / 65.6–70.0 …）。
两边对准的是同一个东西：**支撑接触面**。

> 46mm 落在 `0.2744` 的**厚层段中部**（38.8–41.0 的薄层段之后、42.99–52.6 的厚层段），
> 既不在薄层区、也不在碎层区。E 体积反算层厚 ≈0.27，与 0.2744 吻合 ⇒ **挤出量对，不是欠挤出**。

### 4.2 塔的 Z 跟着层 Z 走（初判写错，已推翻）

初判说「塔层厚写死 0.28，139mm 处比模型高 0.98」——**错**。逐层实测 `G1 Z{..};Tower Z`：

| 层 | 层 Z | 塔 Z | 层 Z − 塔 Z |
| --- | --- | --- | --- |
| 60 | 12.800 | 12.640 | +0.160 |
| 175 | 38.600 | 38.400 | +0.200 |
| 353 | 77.000 | 76.720 | +0.280 |
| 511 | 108.185 | 108.040 | +0.145 |
| 658 | 139.400 | 139.120 | +0.280 |

差值全程 **0 ~ 0.28**，塔**始终低于或追平**层 Z，`Safe Z`(+0.7) 绰绰有余 ⇒ **塔不是本次崩飞的嫌疑**。
（初判那个「塔中心 +0.98」是高度图把原地 `MoreExtrusion` 记成顶面的假阳性，已作废。）

### 4.3 为什么它和本次崩飞相关

- 无 brim（头部配置 `brim_type = no_brim`）+ 46mm 高的细结构 + PETG
- A1 是床动式（i3），`M204 S10000`（空走）/ `S6000`（打印）、空走 `F42000`（700mm/s）
- z-hop 只有 0.4，而且是**原地画一圈**（半径 1.217）—— 层内任何过挤出/毛刺 > 0.4 都会被刮上，
  且刮的是整圈，比直线刮更容易把细件带倒
- ★ **`reduce_crossing_wall = 0`**：「避免跨越外墙」关着 ⇒ 空走可以直接从刚打的墙上穿过去
- ★ **`support_top_z_distance = 0`**：支撑与模型零间隙 ⇒ 支撑被撞歪时模型立刻跟着裂

→ 「底层粘不住 + 空走贴着墙/支撑过 + 0.4 的圈刮一下」是这类崩飞最常见的组合。

## 6. 教训

1. **「崩飞」先问「哪个件」再谈刀路。** 大圆盘、细柱、擦料塔的处置完全不同；本次是圆盘 + 细柱。
2. **判「喷嘴压模型」只能靠高度图扫描，不能靠肉眼比 Z。** 网格 0.4mm、逐条 G1/G0 采样、
   和「已打印最高点」比，是唯一硬判据（本次三次扫描结果一致：模型区全干净）。
3. **层高要按段核对，别按印象。** 作者记得「没开自适应层高」，实测却是 0.278 基准 + 支撑面 0.2 + 过渡碎层；
   而「塔写死 0.28 会越走越高」这个看起来很顺的推论，实测塔 Z 全程滞后 0~0.28 —— **两个方向的直觉都错**，
   只有 `grep` + 逐层比对能定案。
4. **报告里的坐标要标「移动前 / 移动后」。** `towerPos` 与真实落点差 19.5mm 不是 bug，
   但只报一个数就会让人误判碰撞检测失效。
5. **`paint z=` 与落笔 `G1 Z` 不是同一层。** 一个 current、一个 last，按字面配对会造出假 bug（§3）。
