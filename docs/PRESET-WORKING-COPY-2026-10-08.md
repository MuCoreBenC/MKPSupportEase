## 1. 模型：一份官方内容，两条线各存一份

```text
云端官方 v1
   │  用户点「下载」
   ▼
下载管道（SHA 校验 / 旧份归档 / 事件账，一切照旧）
   │
   ├── 官方基线  <appDataDir>/delivery/mkp/presets/<file>.toml
   │      ↑ 程序管、用户看不到、不被用户编辑
   │      ↑ 只用于：和云端比对有没有新版；官方换版本时**只换它**（旧版进 archive/）
   │
   └── 用户工作副本  <appDataDir>/user/presets-mine/<file>.toml
          ↑ 用户看到、编辑、校准、另存、改名、删除、应用 —— **只有这一份**
          ↑ 文件头带血统三行（`# based_on*`）：基于哪一份官方、哪一版、当时原文的 sha256
```

**基线就是现有的内部原件区**（`catalog.path` 指向的落点，`<appDataDir>/delivery/…`）。
没有新建目录：那个路径同时是"云端取哪"（`baseUrl + path`）与"本地放哪"的**唯一路径语义**，
是发布面寻址的锚；它本来就是用户不可见的内部区域。本文之后，文档里把它叫**官方基线区**。

## 2. 七条裁决 → 落点

| # | 裁决 | 落点 |
| --- | --- | --- |
| ① | 下载的瞬间就复制出用户工作副本 | `ipc::catalog` 的下载命令收尾调 `runtime::mine::ensure_working_copy`（单份与批量两条都在）。幂等：已经有了就一个字节不动 |
| ② | 用户永远只操作工作副本 | 预设页**本地表 MKP 档只列 `presets-mine/`**（`presetTree.ts::localRows` 的 `mineOnly`）；应用 / 编辑 / 校准的落点全是它 |
| ③ | 基线对用户隐藏 | 本地表不列官方交付行；`release` 行只服务**切片器档**与**云端表**；云端表照旧是「下载 / 更新」的入口 |
| ④ | 基线不被用户编辑 | 编辑入口只有工作副本（`openEdit` 固定走 mine 线）；官方原件的可操作入口在预设页一个都不剩 |
| ⑤ | 官方更新只换基线 | 下载同一条管道：新字节落基线区、旧版进 `archive/`；**工作副本不碰**（`ensure_working_copy` 已有不动） |
| ⑥ | 编辑直接改工作副本，不再另存 | `改这份 → 保存` = `mine::save_back`（写回它自己，不产生第二份）。官方 → 我的那条"另存"（`copy_release_as_new`）**退役** |
| ⑦ | 校准 offset 写进工作副本 TOML | `ipc::mine::save_preset_calibration`（按注册表定位 `toolhead.offset.x/y/z`，`presetdata::patch` 只换值）；初值读 `ipc::mine::get_user_copy_for`；`save_offsets` / `index/offsets.json` 退役 |

## 3. 「官方换版了没有」怎么答（基线的用途）

工作副本的血统三行记着**当初那份官方原文的 sha256**；目录（catalog）登记着**当前那一版**
的期望 sha256。两者一比就是现成的三档（`runtime::mine::based_on`）：

```text
血统 sha256 == 目录期望 sha256   → current（官方没换版）
血统 sha256 != 目录期望 sha256   → outdated（官方换版了）：界面说「官方已换新版」
目录里已经没有来源那份            → unknown（说不出新旧）
```

**云端的"有没有新版"不看工作副本自己的字节**（用户改过，比它必然不同），
只看这条血统比对 —— 这正是"基线只作与云端比对"那句话的兑现方式。

## 4. 交互现状（用户看到的）

```text
本地表 · MKP 档          只有「我的一那份」（presets-mine/）
云端表 · 仓库行          官方有什么；「下载 / 更新」入口
云端表 · 交付行          在盘上是什么状态（已下载 / 有更新 / …）—— 四态照旧
工作副本行               应用 / 改这份 / 另存为一份新的 / 重命名 / 在 Finder 中显示 / 删除
台账                     MKP 档 =「仓库 N · 我的 M」（不再有「本机」：官方副本不进用户世界）
```

- 首页「下载并应用」：下载 → `ensureUserCopy`（幂等补齐）→ 应用**工作副本**（mine 线）。
- 校准页：有工作副本 → 初值读它、保存写它；没有 → 显示官方默认值，**保存按钮灰着**
  （title / 卡片提示说清「先下载这份预设」—— 校准值不落别处）。

## 5. 退役与新增（命令面）

| 命令 | 变化 |
| --- | --- |
| `save_offsets`（`index/offsets.json`） | **退役**（连同 `fsx::paths` 的 `Root` / `resolve` 抽象与 `index/` 预建目录）；校准读写全走用户线 |
| `copy_release_as_new` | **退役**（下载即得工作副本，"官方 → 我的另存"没有存在理由了） |
| `ensure_user_copy(fileName)` | **新增**：幂等补齐工作副本（下载收尾与首页应用前都用它）；基线不在 / 字节不干净 → 报错说清「先下载」 |
| `get_user_copy_for(machineId, versionId)` | **新增**：这台机型 / 这个版本「我那一份」在哪 + 它带的校准值（校准页初值与保存落点） |
| `save_preset_calibration(path, axes)` | **新增**：三个值按注册表定位写进工作副本（注释 / 键序 / 血统一个字节不动） |

Rust 判据：`runtime::mine` 的 `the_first_download_leaves_a_working_copy_and_never_overwrites_it`
（首次生成 + 二次不动）、`ensure_working_copy_refuses_non_presets`、
`calibration_reads_axes_and_speed_from_the_registry`、`calibration_is_none_when_values_are_not_there`。

## 6. 探针（浏览器层）

`scripts/probes/presets.mjs`：

- 5 节：交付四态的**本地表**断言改成「官方交付行一行都不许出现」；四态改到云端表量。
- 5e：改为「用户世界只有他那一份」（本地表不列官方交付行、我那份照旧在）。
- 5f：认得出 / 认不出改到云端表；内容存疑的字节**不进本地表**（构造上不给应用 / 改）；
  云端表菜单里没有「另存为一份新的」。
- 5k：删「官方 → 我的另存」全程，保留「我的 → 我的另存」。
- 5m：第十三层只对「我的文件」有落点（官方基线不进用户世界）。

## 7. 为什么不是"官方可见 + 用户另存"

那版方案（官方行与 `（已修改）` 副本并排可见）最大的问题不是技术，是**用户心智**：
"我该用哪个 / 哪个是我的 / 为什么下载一个东西出现两个"。改回"下载即复制"之后，
用户世界永远只有一份；后台多一份（基线），用户世界中不多一份 —— 后台的账由程序自己管。

## 8. 边界（本轮明确不做）

- **不做"把改动挪到新版官方"（合并）**：作者 2026-10-02 已降级，不进主线。官方换版本后
  用户的工作副本照常用、照常改，界面说清「官方已换新版 / 我的基于旧版」。
- **不做数据迁移**：旧盘上"下载过但还没有工作副本"的状态，重新点一次「下载」即可补齐
  （`ensure_working_copy` 幂等），没有迁移代码、没有启动兜底。
- **基线没有用户可见的删除入口**：它是程序管理的内部内容（随检查更新自动换代）；
  要清理就删 `<appDataDir>/delivery/…` 里那份，程序会把它当"未下载"。
