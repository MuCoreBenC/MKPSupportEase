## 2. 一页速览（已确认的事实，详情见各图）

- **套餐是独立业务对象**，正文在 `presets/bundles.toml`，内容是一份**资产 id 清单**（`assetRefs`，至少一条 BBS 切片器预设），**不含任何参数值**，不参与渲染，后处理也不读它。（`02-flows.md` §1）
- 套餐有**两档指向**：机型 `defaultBundle`（机型默认）与版本 `recommendedBundle`（一版一套）；都为空时回退机型默认。（`derive.rs:298-317`、`derive.rs:327-347`）
- 产物 TOML 的**段/键/顺序由参数注册表决定**（`section` / `layout.order` / `tomlKey`），值来自三层：版本层 > 机型层 > 出厂默认。（`resolve.rs:114-132`、`build.rs:339-411`）
- **后处理链与预设/套餐只有一条细线**：产物 TOML 的绝对路径被拼进切片器钩子 argv（`ipc/mod.rs:626-654`），钩子用 `preset::load_ir` 把它翻译成 IR。后处理不读 `bundles.toml` / `assets.toml` / `public/bbs/*`。（`02-flows.md` §3）
- 交付面四份文件的读取者：`catalog` 客户端必需；`source` 客户端寻址必需；`manifest` **仅工作台**；`publish-serial` **仅工作台**。（`04-data.md`，详见 [`../DELIVERY-ARCHITECTURE-RESEARCH.md`](../DELIVERY-ARCHITECTURE-RESEARCH.md) §3）
- **IR 是后处理核心的入口契约，不是共享模型**：`mkpse-postprocess` 零内部依赖，适配层 `mkpse-preset` 单向依赖它做 TOML → IR；后处理不读 TOML、不认套餐、不认工作台（`06-cores.md` §2.1/§4）。
- **流程相邻 ≠ 架构耦合**：套餐属配置核心（资源组织规则），交付核心只管字节与身份，后处理只管 G-code + IR；三者靠"产物 TOML 文件"这一稳定格式相接，不是靠互相调用。（`06-cores.md` §1/§3.7）
- **BBS 不是后处理依赖**：它落 `<appDataDir>/assets/bbs/…`，被 BBS 页读取、可一键复制进切片器目录，但 G-code 内核与钩子一处都不读（`04-data.md` §4.1）。
- **机型尺寸不进产物**：`render` 只用机型 id；尺寸进 `catalog.machines[].dimensions` 与 `revision`，不进 `structureSignature`。改尺寸不需要重新生成产物，但要让客户端看见需重发目录（`04-data.md` §4.2）。
- **套餐页不走草稿**：两个写操作都即时落盘；`Patch::SetBundle` 草稿路径前端无构造点（`api.ts:806` 仅类型），属潜在死路径（`05-problems.md` A10）。

## 4. 维护约定

1. **每条结论带证据**：`文件:行` 或「未核实」。没有行号的推断不得写成结论。
2. **只写现状与目标**，不写沿革（AGENTS §8.4）。历史去 `git log -p`。
3. **新增页面/命令时**：先更新 `01-product.md` 的页面表与 `03-tech.md` 的 IPC 表，再改代码 —— 否则 KB 立刻过期。
4. **核对日期**：每张地图头部写「最后核对：YYYY-MM-DD + 核对范围」；改动主链后更新对应章节。
5. **不把 KB 当裁决场**：架构裁决仍在 `docs/ARCHITECTURE.md` / `PUBLISH-ARCHITECTURE.md` / 作者口头裁决；KB 只负责"现在是什么样"。
6. **证据工具**：本仓可用 `scripts/probes/*`（浏览器探针）与 `.scratch/repomix/repo.md`（整仓打包，13 MB，按需 grep，不要整份喂给模型）。
