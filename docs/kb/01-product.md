## 1. 顶层结构：一个工作台，8 个页面

导航固定 8 项（`src/workbench/App.tsx:874-890` 的 `case` → 组件）：

| 导航 | 组件 | 一句话职责 | 是否主链 |
|---|---|---|---|
| 机型与版本 | `views/MachinesPage.tsx` | 机器=存在与启用、尺寸、版本清单 | ✅ |
| 参数台 | `sheet/ParamSheetPage.tsx` | 编辑机型层/版本层参数值（草稿 → 保存） | ✅ |
| 套餐 | `views/BundlesPage.tsx` | **交付的真相**：装什么文件、谁在用它、改指向 | ✅ |
| 资产库 | `views/AssetsPage.tsx` | 图标/模型/BBS 预设/引导图等资产台账 | 桥（被套餐引用） |
| 标注台 | `views/AnnotatePage.tsx` | 引导图标注（资产的一种编辑器） | 旁路 |

## 2. 主链页面（做深）

### 2.1 套餐（`BundlesPage`）

页面自述：「**套餐 = 交付的真相（bundles.toml）—— 装什么、谁在用、改指向，都在这页**」。

左列：套餐列表。每项显示 **`N 个版本用它`** 与 **`装了 N 个文件`**。
右列（选中一份后）：

| 区块 | 显示什么 | 能做什么 |
|---|---|---|
| 标题栏 | 套餐显示名 + id | 编辑 / 复制 / 删除 |
| 机型默认跟着它 | `defaultBundle` 指向本套餐的机型 | 只读（改指向在机型页或下方） |
| MKP 预设（N） | `assetRefs` 里 `mkPreset` 类的文件 | 移出；「已生成」表示交付里已有该产物 |
| 切片器文件（N） | `assetRefs` 里 `slicerProfile`（BBS）类的文件 | 移出；「改套内容…」换文件 |
| 被哪些版本指向（N） | `recommendedBundle` 指向本套餐的版本 | 只读 |
| 把版本指到这个套餐 | 多选版本 + 选定数量 | 「确认指向」批量改指向 |

底部汇总：「`N 个套餐 · 装了 M 个文件`」。

**认知要点**（与代码一致，见 `02-flows.md` §1）：

- 套餐装的是**文件引用**，不是参数值、不是"配方"。
- 一个版本只能指一个套餐（一版一套，`AGENTS.md` 的"一版一套"）；没指就回退机型默认。
- 「装了 N 个文件」不等于「这 N 个文件都是本套餐独有」—— 同一份 BBS 可以被多个套餐引用。

### 2.2 参数台（`ParamSheetPage`）

- 三种视角：**单版本** / **版本对照** / **机型基底**（走查按钮文案）。
- 左树选机型 → 版本；右表格按"段"分组（注册表的 `section` / `layout.order`）。
- 编辑写进**草稿**（内存 + 撤销栈），不立即落盘；保存才写 `presets/`。
- `↩` 表示"当前值来自哪一层"（机型层 / 版本层 / 出厂），可回退继承。

（参数分层与合并规则见 `02-flows.md` §2。）

### 2.3 机型与版本（`MachinesPage`）

- 左：品牌 → 机型树；顶部「筛选品牌与机型」。
- 右：身份（显示名 / 内部名）、尺寸（`编辑尺寸`）、禁区（`编辑禁区`）、版本列表（`新增版本`、每版一行的"配置/明细"）。
- 「已保存 · 查看改动」与底部「未保存改动（N）」说明这里有**结构编辑**（与参数值编辑不同的写入路径）。
- 启用/停用是机型上的一个布尔（`enabled`）；**停用不等于删除**（KB `05-problems.md` 记录了它当前在各模块的口径不一致）。

### 2.4 生成与发布（`BuildPage`）

页面结构（走查 + 代码）：

| 区块 | 内容 |
|---|---|
| 顶栏 | `阻断 N · 待办 N · 提示 N` + 「已保存 · 查看改动」 |
| 左侧「检查」 | 逐条问题卡（每条带「去处理」），例：`有 2 个文件没进任何套餐`（产品文案明确：**不分配套餐的 profile 是正常状态，不是待修的错**） |
| ① 生成 | 「生成本次待更新（N 份）」；分组列出 MKP 预设 / 目录与清单 / 发布定稿 / 范围外文件；每行状态（已生成 / 待更新 / 待删除 / 未纳管）+「重新生成」 |
| ② 交付预设 | 发布前状态（资产字节漂移、目录上次重算时间）、`发布历史` / `发布` |
| 软件版本 | 当前版本、`发布软件版本`、`刷新`、`history.json` 原文 |

两条发布链**互不相干**（`AGENTS.md` §4/§4.5）：①「发布」= 交付预设（`presets publish`）；`发布软件版本` = 客户端 `.app` 发版。

## 4. 跨页面的三条常驻状态

1. **草稿（未保存改动）**：参数台/机型页都会显示；顶部「已保存 · 查看改动」可看 diff。草稿在内存，不在磁盘。
2. **检查报告**（`阻断 / 待办 / 提示`）：由后端 `wb_preflight` 算，页面只展示；每条带 `去处理` 落点。
3. **底部状态栏**：数据根路径（`MKPSupportEase/presets`）、「已保存 / 有未保存改动」、「快照已跟上」、撤销/重做。
