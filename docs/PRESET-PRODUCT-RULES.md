> - **参数对比台**是**独立常驻工具**：只在**用户自己的本地预设**之间比（2~3 份，
>   全部列可编辑），差异行给**显式**「采用此值」；不做文本 diff、不做三方合并；
> - **「恢复默认值」改基准**：这份我的预设当初那一版官方的默认值（从 baseline 取）；
>   没有基准就回退出厂值；
> - **数据源地址保存即生效、不许要求重启**。

## 1. 页面结构：位置 × 类型两个维度

预设页是**两张互不相干的表**，由两个轴交叉出当前这一张：

```text
类型   MKP 配置 │ 切片器配置          ← bbs / orca 等非 MKP 的都算「切片器配置」
位置   本地     │ 云端
```

- **两档按目录的 `kind` 分流**（不靠扩展名猜）：`mkp_preset` → MKP 配置；
  `bbs_config` / `orca_config` → 切片器配置；**图标（`icon`）/ 模型（`model`）
  哪一档都不出现** —— 登记在目录里 ≠ 进预设页（它们是资源，由自己的资源体系消费）。
- **MKP 档只有一张表**（2026-10-08 三次改判：**资源库**）：官方那几行（目录登记的当前版）
  与我的那几行（`presets-mine/` 扫盘）**并排**，`来源` 只是副标题上的一枚小字
  （「官方 · MM-DD」/「我的预设 · 源自官方 X」）；官方那一份本机有没有字节**不显示** ——
  点「使用」时按需取回。**这一档没有"本地表 / 云端表"之分**，位置那一轴也不出现。
- **切片器档照旧两张表**（本期不动）：本地表 = 你这台机器上有什么（官方副本 + 我的文件）；
  云端表 = 菜单上有什么官方文件（已分配 `bundled` + 可选 `optional`）；
  **仅归档（`archived`）的一处都不出现** —— 仓库里有 ≠ 客户端能拿到，不上菜单就下不了。
- 一个官方文件下载之后：云端表说"仓库里有这个东西 / 盘上是什么状态"，
  本地表说"**你那一份**在这儿"（工作副本）。两张表各回答一个问题，不合流。

依据：预设页页头 + `presetTree.ts` 类型门槛 + 第二圈菜单表。

## 2. 本地页面的字段与排序

- 列：**名称 / 机型 / 版本 / 时间 / 大小 / 来源 / 状态 / 操作**；切片器那张表多两列
  （喷嘴 / 层高 —— **只有切片器有这两个字段**，所以只有那张表里有）。
- 来源列说这份文件住哪：官方（下载区 `mkp/…`）或 `presets-mine/…`；
  认不出机型的用户文件照实写「未标机型」（`kind` 只有扩展名说了算，`.json` 照实认不出）。
- 大小 / 时间：**交付行的大小是 catalog 登记的真值**（字节数）；其余行的真机上由后端扫盘给
  （假后端是按 path 稳定推的演示值，前端一行不编）。
- 「我的文件」按路径升序排（判据钉着）；**置顶是纯前端偏好**（localStorage），
  只影响这一页的显示顺序 —— 它不是产品数据，不进任何底账。
- 表格右上角「共 N 项」是**当前这张表筛后的真计数**，不是两张表的数并排。
- 它旁边的台账**也跟当前类型档走**：仓库 = 这一档类型在全机型下的文件数、
  我的 = 用户文件里属于这一档的（认不出类别的两档都算）。
  **MKP 档没有「本机」这一格**（2026-10-08：官方基线不进用户世界，用户只有他那一份）；
  切片器档照旧带「本机」（官方副本总数，老契约 `getLocalFiles` 的读数）。
- 搜索按文件名 / 路径过滤（纯前端）；机型下拉只换当前的机型档。

依据：预设页页头逐行交代表 + `runtime::mine` 升序判据 + 第十层（`kind` 认不认出）
+ 第十五层（台账跟档）。

## 3. MKP 配置的"应用"唯一性

- 「已应用」是一条**独立的事实**，**全局唯一**：底账 `run/active-preset.json`，
  同一时刻只有一份生效（"涂胶笔同一时间只跑一套"）。
- **不是一个可以从别的数据算出来的派生量** —— 前端不许自己推「当前机型 + 默认版本」那套。
- **两条线都能成为使用中**（官方线 / 用户线）：`origin` 说这一份住哪条线；
  官方线**不存路径**（落点由目录给）、用户线存 `path`（用户目录可以自己分文件夹）。
- 应用只有一个入口（`applyActivePreset(fileName, origin?, path?)`），
  两道入口闸按各自的线：**官方** = 盘上字节与目录登记逐字节一致；**用户** = 在
  `presets-mine/` 那一格里 + 是能读的 TOML（第九层）。
- 应用时写指纹（官方线据此查"盘上那份漂没漂"）；撤销使用 = `clearActivePreset`（幂等）；
  切换应用 = **后应用赢**（一条）。
- 界面上「已应用」只画一条状态条（不跟机型筛选走，筛没了有「定位」）。

依据：第七层 / `runtime::state` 判据 / C4 收口。

## 4. 切片器配置没有"应用"这个动作

- 切片器的「生效」**不是**设为当前配置，而是**复制到切片器自己的 profile 目录**：
  `copyToSlicer()`，状态只有**已复制 / 未复制**，操作列是 [复制]。
- 切片器那张表**没有"已应用"、也没有替代状态条** —— 那一排位置给的是喷嘴 / 层高筛选。
- 真机现状：**「已复制」状态读已经接了真后端**（`get_slicer_copied`）；
  **「复制」这个写动作还没接**（`bridge` 里 `notWired`，界面如实说）。这一条见
  `docs/PROJECT-AUDIT.md` ③，属"差一半"不是"没做"。
- **切片器的交付文件**（目录里 `bbs_config` 那类，云端表能下载 / 更新）在**本地表里
  没有可点的动作**：不能「应用」（使用中指针只认 MKP），「复制」那条路只认资产库的
  asset id —— 给灰字 + 说明，不给点了没反应的按钮。

依据：预设页页头（两种「生效」分开）/ `usePresetData` / 探针 + 第十五层（交付行动作边界）。

## 5. 云端页面与三个状态

- 原定的"三个状态"落地成**交付四档**（`ReleaseFileState`）：**未下载 / 已下载 /
  旧版本 / 内容异常**。三个读合起来才够：`getDownloadedFiles`（与目录一致）+
  `getStaleFiles`（盘上有、但不一致）+ `getDeliveryTrust`（**那不一致的字节认得出是哪一版吗**）。
- **「旧版本」** = 盘上那份与 `archive/` 里某一版逐字节相同（证据是归档路径）；
  **「内容异常」** = 与目录、归档都对不上 —— 这台机器上查不出它属于哪一版。
- 云端表每行自己标「未下载 / 已下载 …」；批次行只含"未下载 + 旧版本 + 内容异常"。
  （2026-10-08 改判：MKP 的四态**只在云端表量** —— 本地表 MKP 档只有工作副本。）
- **「盘上不一致」与「云端有新版」是两件事**：后者是比**目录指纹**（见 §6），
  与本机字节无关 —— 混成一句「需更新」就都答不清。
- 仅归档的文件客户端**完全不知道它存在**。

依据：第六层 / `runtime::delivery::trust_entries` / 探针第 5e~5f 节。

## 6. 更新提示

- 「云端有没有新版」= 比**目录指纹**（`checkRemoteUpdate`，两端共用契约 R11）。
  **显式动作**：不进首屏、不自动跑 —— 启动零网络是铁律。
  （2026-10-02 注：「同步」页退役后这一件事**暂时没有 UI 入口**；命令与机制保留，
  Bootstrap 那一刀「预设页进入时后台检查一次」接上。启动零网络这条判据一个字不变。）
- 更新动作 = **同一条下载管道重跑**（不是第二个命令）：下载 → 校验 → 落盘 → 旧份归档。
- 批量那一行的字按这一批里有什么算（「下载」/「更新」/「下载并更新」）；
  范围 = 机型 + 类型，**不受搜索词影响**；已下载的不进来。

依据：第二圈 R11 / `runtime/net` 判据 / 探针。

## 7. 下载

- **下载地址 = 数据源地址（`run/preset-source.json`）+ catalog 的 `path`**；
  地址是配置、不是说明书的一部分 —— 没配就**如实拒绝，不猜一个 URL 出来**。
- 管道：`Source` → **落盘前校验**（SHA / 大小）→ 原子写 → **`<catalog.path>`**
  （唯一路径语义；预设那一类是 `delivery/mkp/presets/…`，即**官方基线**）。
- **官方是模板、我的才是工作文件**（2026-10-08 三次改判）：MKP 那一档的「使用」
  （`use_official_preset`）在本机没有字节（或与目录对不上）时**按需取回**，
  再写成当前使用；要改官方那份就显式「另存为我的预设」（`copy_official_as_mine`）。
  **下载 / 使用都不再自动产生副本** —— 旧的"下载即得工作副本"退役。
- 健壮性：**运输类故障退避重试**（连接 / 超时 / 解析 / 被掐），
  **内容类一次都不重试**（404、500、字节超了）；超时必有值（服务端不回答也不许吊住调用方）。
- 进度：一次调用一路水位（Tauri `Channel`）；批量**固定并发在 Rust 侧**（前端不发明并发），
  返回按请求顺序、**逐份给结局**。
- **下载区初始为空**：用户没下载的东西不提前塞进用户目录（catalog 是唯一例外 —— 它是软件说明书）。
- **下载 ≠ 使用**：下载落基线并铺一份工作副本，应用才写底账（`run/app-state.json`）。

依据：第二圈（真数据源上线）/ `runtime::net` 12 条 + `delivery` 13 条判据 / 铁律 3。

## 8. 更新与归档

- 更新 = 重跑同一条管道；**旧份自动进 `archive/`**（`archive/<catalog.path>`，
  与交付面同形）—— **保留最早一份**：不覆盖、不删。
- **更新换的是官方基线**（2026-10-08）：用户的工作副本**不碰** —— 它照常用、照常改，
  界面照血统说清「官方已换新版 / 我的基于旧版」（§14）。
- 归档兼一个身份：**判定"盘上这份是旧版本"的证据**；第二份证据是被归档的旧目录
  （`archive/catalog.json` —— 归档槽被占了也认得出更早那一版）。
- 界面两档按钮字不同：旧版本「**更新**」、内容异常「**重新下载**」—— 同一条管道，动词不同。
- **归档管理不在这一层**：删除 / 恢复**连命令都没有**。

依据：`runtime::delivery` 归档 3 条 / 第六层 / HANDOFF §7。

## 9. 发布时间作为用户可见的版本号

- 交付文件本身**没有版本号字段**；"这是哪一版"由两样承担：
  **发布时刻**（TOML 头注释的 `release_time`；云端目录项的 `at`）与**目录指纹**（revision）。
- 血统三行里的 `based_on_release_time` 记的就是来源那一版的发布时间 ——
  于是"我这份基于哪一版官方"**换一台电脑也读得出来**。
- 界面时间列认三种写法：纯日期（演示值）/ ISO（发布或下载时刻）/ 老 stamp（`9/30 16:12`）——
  **凑不出年份就不给年份，不编**。

依据：`runtime::lineage` / `store/package.ts` 时间格式化 / 第七层。

## 10. SHA 与失效判定

- **官方线**：盘上那份与目录登记**逐字节一致**才可信（SHA / 大小在落盘前校验，
  落盘后按目录复核）。
- 盘上不一致时，**先问"这是不是我们发过的字节"，再问"云端有没有新版"**：
  ```text
  盘上这一份 vs 目录登记的当前版本
    ├─ 逐字节相同               → 就是当前这一版
    ├─ 与 archive/ 里某一份相同   → 旧版本（认得出是哪一版）
    └─ 哪儿都对不上              → 内容异常
  ```
- **内容存疑的那两档不许用**：不能应用（SHA 闸）、不能编辑（取原文先核 SHA，
  漂了报 `SHA_MISMATCH`）、不能复制（界面直接不给）—— **只能重新下载**。
- **用户线不查 SHA**：外部修改是正常事（那份是用户自己的）；**只有"读不出来"才拦**
  （第九层：存在 + 在 `presets-mine/` 里 + 能读 + UTF-8 + TOML 语法能解析）。
  客户端**不复制 `mkpse-preset` 的 schema、不建第二套 Preset 真相** ——
  语义合法性留给真正的 Preset 能力在应用 / 编辑入口上回答。

依据：第六层 / 第九层 / `delivery::official_text` / 总纲 §1③。

## 11. 基线只读（原「云端原件只读」，2026-10-08 改判）

- **官方模板**（`<catalog.path>`，预设的是 `delivery/mkp/presets/…`）**永不直接编辑**：
  只有"云端换版本"能替换它；它**对用户不可见**（来源那一行小字只说「官方」）——
  没有编辑 / 删除入口；要改就先「另存为我的预设」（2026-10-08 三次改判）。
- 「修改」= 把**工作副本**的正文复制进临时文件（`run/app-state.json` 的 draft 格），
  用户改的是它；点保存**写回工作副本自己**（不产生第二份）。
- **"只读"是文件归属的属性，不是"能不能被使用"的属性**：使用中的那一份是工作副本
  （mine 线）—— 下载那一刻它就有了。

依据：总纲 §1③ 五条 / 第五 / 八层 / 第七层 / [`PRESET-WORKING-COPY-2026-10-08.md`](PRESET-WORKING-COPY-2026-10-08.md)。

## 12. Finder 里复制一份 → 与云端脱钩

- 用户在 Finder / 资源管理器里把文件拿进拿出（复制 / 压缩 / 发人 / 备份）**不经过程序**；
  自己丢进 `presets-mine/` 的那一份就是一份**用户文件**：没有血统就照实"没有来源"，
  不查 SHA、不参与交付四档。
- 用户文件的管理动作全是**文件级**（改名 / 删除 / 另存为一份新的 / 导入 / 在 Finder 中显示）——
  **只动文件，一个状态都不碰**（使用中指针 / 草稿 / archive）。
- **「在 Finder 中显示」就是"拿出去"的全部**：之后复制 / 压缩 / 发给别人随用户，
  **程序不再造第二套"分享 / 导出"**（作者裁决，见 §18）。
- **外部管理只给「我的文件」**：官方基线住程序自己管的区域（用户世界里没有它的行），
  **读不出来的那份也能显示**（文件管理同族：打开文件夹不吃内容）。

依据：第九~十三层 / `runtime::mine` 判据 / 探针第 5m 节。

## 13. 用户的工作副本（原「用户修改副本」，2026-10-08 改判）

- **写用户根只有三条路**（不许合成一个"存一下"）：
  ```text
  下载的收尾  基线落下 ──▶ 我那份也在：presets-mine/<原名>（幂等，已有不动）
  我 那 份 ──「改这份」──▶ 临时文件 ──「保存回我这份」──▶ 写回它自己（同一路径，不产生第二份）
  我 那 份 ──「另存为一份新的」──▶ 按字节复制成同格另一份新的（血统原样带过去）
  ```
  血统只在"从官方来源建副本"时从**来源**算（下载的收尾就是这种）；写回时**照抄原来那三行**
  （出处没变）。（改判前的"官方那份 → 另存成 `（已修改）`"：后端能力仍在、测试仍锚着它，
  界面不再给入口 —— 编辑对象只有工作副本。）
- **打开又保存 = 逐字节不变**（什么都没改 = 用户那份内容没变）。
- **关闭抽屉不丢**：草稿在盘上（边改边存），回头点「改这份」接着改；
  丢草稿只有 footer 那颗「放弃这次编辑」。
- **保存不校验**：用户自己写下去的东西由检测如实说（§10 用户线那半），不替他改主意。
- 编辑器里给的是**正文**；从官方来源建副本（下载的收尾）写下去的 = **官方原文 +
  头注释块里三行血统**（`# based_on: delivery/mkp/presets/…` / `based_on_release_time` /
  `based_on_sha256`），**正文逐字节不动**；不许改用 `[metadata]` 表
  （多一张表 = 读取面报"这份预设比本程序新"）。
- **校准值也写进它**（2026-10-08）：`save_preset_calibration` 按注册表定位改
  `toolhead.offset.x/y/z` —— 注释 / 键序 / 血统三行一个字节不动；没有工作副本就存不了
  （保存按钮灰着，提示"先下载这份预设"）。

依据：第五 / 八层 / `runtime::lineage` 判据 / 第七层 / [`PRESET-WORKING-COPY-2026-10-08.md`](PRESET-WORKING-COPY-2026-10-08.md)。

## 14. 与云端更新完全脱钩

- 用户那份基于旧版官方时，界面说清「**官方：v2 / 我的：基于 v1**」——
  它照常能看、能用、能改（"基于旧版官方"**不是坏文件**，行上多一枚中性徽章，不是警示色）。
- **不自动合并、不自动迁移**："把改动挪到新版官方"作者 2026-10-02 已降级为
  **暂不做、不进主线**（那会把 Preset 系统变成版本迁移工具；将来若做，也更可能是
  "以新版为基础重新修改"，让用户自己重新调，而不是程序猜怎么揉）。
- 官方换版本不会碰用户那份；用户那份也不会回写官方（§11）。

依据：第七层 / HANDOFF §5。

## 15. 归档

- ★ **MKP 档不再消费它**（2026-10-08 三次改判：官方只有一个当前版，归档抽屉退场）：
  写盘那一支还在，**只服务切片器档**（下一期与切片器一起收口）。
- `archive/` 曾是**官方版本生命周期**的一部分：换版本时旧份进这里，**保留最早一份**。
- 它**不是用户修改历史**：界面上那一格说的是"这一份以前的官方版本还有几个"，
  不是"你改过几版"。**用户删自己的文件 = 真删除**（没有垃圾桶、也没有归档）。
- 界面：交付行展开详情里「旧版本 N 份」→ 抽屉，能看正文；**只读**。

依据：第三 / 六层 / 第十层边界 / 总纲 §1③ 第四条。

## 16. 外部导入 TOML 的校验

- **导入 = 把外部文件纳入"我的文件"所有权范围**（第三条"创建"路），
  **不是安装 Preset** —— 落点固定用户根。
- 收：`.toml`。**不收**：ZIP / 备份包（注册表留了认领的口子，等「备份与恢复」注册导入器）、
  `.json`（要收就在注册表加一条）。
- **内容不校验**：坏的 TOML 也进得来（进来之后 §10 用户线那半如实说它读不出来）；
  **有血统原样带、没有不编造**。
- **重名不是失败，是改名流程**：界面开「导入：有同名文件」那一格（输入框预填原名，
  不覆盖、不自动改名）；取消 = 这些没进来，别的照常（一份错不拖累别人）。
- **一个状态都不碰**（使用中指针 / 草稿 / archive）。

依据：第十二层 / `runtime::import` 8 条判据 / 探针第 5l 节。

## 17. 本地文件被外部删除

- 列表**以磁盘为准**：被外面删掉的那份，重读之后就不再显示；列表刷新即消失。
- 应用 / 读正文时文件已经不在了：如实报"找不到"（不去猜、不去别处找）。
- **正在使用的那份被外面删了**：`run/active-preset.json` 还指着它 —— 落点解析不到，
  视为"**漂了**"（`intact:false`），界面照实说；**不猜路径、不静默改指针**。
- 程序阻止不了外部删除（文件在用户手里）；保证的只有一条：
  **不把不存在的东西说成存在**。
- **【待作者定】**要不要"启动对账"：扫 `run/` 与用户根，把悬空的指针 / 孤儿草稿
  显式清掉或提示 —— 见 `docs/PROJECT-AUDIT.md` ⑦（与「备份与恢复」的规格一起定）。

依据：`runtime::state` 判据 / `active_target` / 第九层读闸 / 外删的报错话术。

## 18. 第一版明确不做的部分

以下都是**登记在案的边界（不是遗漏）**：

- **「分享」整块不做**；**单文件「导出」暂缓**（"拿出去"由「在 Finder 中显示」解决；
  将来真正的导出是「设置 → 备份与恢复 → 导出备份 ZIP」）。
- **用户文件没有归档**（删 = 真删）；跨文件夹移动 / 文件夹管理不做。
- **复制不自动改名**（目标存在就拒，让用户自己换名字）。
- **"把改动挪到新版官方"（合并）暂不做**（§14）。
- **语义合法性客户端不判**（给真正的 Preset 能力留位，§10）；**客户端不复制 Preset schema**。
- **ZIP / 备份包现在不导入**；`.json` 不收。
- **仅归档的文件客户端完全不知道它存在**。
- **报告页 / 设置页当前是空态**（明说"本版未接入"，不是白屏）。

依据：第三圈各层登记（HANDOFF §4/§5）+ `docs/PROJECT-AUDIT.md` §1「已登记的不做/暂缓」。
